# 締切トラッカー

仕事や生活の締切を管理し、**iPhone のカレンダー通知**と**Discord・Gmail への連絡**につなげる個人用 Web アプリです（利用者 1 人想定）。

フロントエンドはフレームワークなしの静的ページ（HTML / CSS / JavaScript）、データの保管と定期通知は **Cloudflare Workers + D1** が担当します。Cloudflare の無料枠内で動作するため、ランニングコストは 0円 です。

```text
アプリ（Worker から配信） ──→ Worker の API ──→ D1（締切データ・世代バックアップ）
 ├─ 締切を登録・編集             │
 ├─ .ics を書き出す ──→ iOS標準カレンダー（カテゴリごとに決めた日数前・当日に通知）
 └─ アクセスキーで同期           ├─ Cron ──→ Discord（朝・夜の再通知・日曜は週次レビュー）
                                 ├─ Cron ──→ 自分宛ての Gmail（モーニングブリーフ用）
                                 └─ /ics/<トークン>.ics ──→ カレンダーの購読（メモなし）

```

> **旧環境について**：GitHub Pages ＋ 非公開リポジトリ `deadline-data` ＋ GitHub Actions による運用は終了しました。アプリ側の GitHub 同期および Discord への直接送信コードは v4.0 で削除済みです（詳細は「[旧環境（終了）](https://www.google.com/search?q=%23%E6%97%A7%E7%92%B0%E5%A2%83%E7%B5%82%E4%BA%86)」および `docs/cloudflare-migration.md` を参照）。

## 1. 設計の考え方

* **通知は外部アプリに任せる**
静的 Web アプリはページを閉じている間に通知を出せないため、通知を外部サービスへ委譲しています。確実にアラームを鳴らしたい予定は **iOS 標準カレンダー**へ、毎日の状況をざっと把握したい一覧は **Discord** へ任せ、アプリ本体は「締切の管理と見える化」に徹します。
* **締切と定期予定を分ける**
定例会議や習慣などの繰り返し予定が混ざると、本当に期限のあるタスクが埋もれます。タブを分離し、カレンダー上も色で区別します。
* **残り日数を主役にする**
一覧では残り日数を大きく表示し、カード下部の「経過メーター」で進捗を可視化します。メーターは単発予定なら「登録日〜締切」、定期予定なら「前回〜次回」の割合を示し、期限切れ・当日・3日以内・7日以内で色が変化します。

## 2. 主な機能

### 2.1 締切・予定の管理

* **基本操作**：登録・編集・削除・完了（完了分は「完了」タブへアーカイブ）。カードの操作は「完了にする」と「…」メニュー（カレンダー出力・編集・雛形に保存・削除・延期・休み設定）に集約しています。
* **1行クイック入力**：一覧上部の入力欄に `明日 17時 レポート提出` や `毎週水曜 17:00 バイト #バイト` のように入力すると、日時・繰り返し・カテゴリを自動解析して下書き状態で登録画面を開きます。テンプレート名だけの入力にも対応し、入力欄下の「書き方の例」で書式を確認できます。
* **今日の一手**：その日に着手する締切を 1 日 3 件までマークできます（「…」から「今日の一手にする」「明日の一手にする」を選択）。
* 一覧の最上段に 3 行の専用枠として固定表示され、タップで該当カードへ移動します（完了した項目はその日の間「済」と表示）。
* 前夜に「明日の一手」を設定しておくと、翌朝 6:47 の Discord 通知およびメールの冒頭に「◎ 今日の一手」として掲載されます。
* 翌日への自動持ち越しはなく、完了・延期・休み設定で解除されます（設定の「このアプリについて」で直近 14 日間の利用日数を端末ごとに集計表示）。


* **メモ内チェックリスト**：メモ欄に `- [ ] 手順` や `- [x] 手順` と書くと、カード上でタップ切り替え可能なチェック欄になります。
* カード 2 行目に進捗（`☑ 3/7`、全完了で `☑ 7/7 済`）を表示し、6 行目以降は「ほか N 件」に折りたたみます（完了済みカードおよびカレンダー上の繰り返し複製では操作不可）。
* テンプレート保存時にメモも複製されるため、「入稿チェック」などの手順付き雛形として活用できます。Discord やメールには `- [ ]` 形式でそのまま出力されます。


* **期限切れの延期と削除の取り消し**：
* 期限切れ項目は「…」から翌日の同時刻へ「明日に延期」でき、トースト通知から元に戻せます。
* 誤って削除した場合は直前 1 件をトーストから取り消せるほか、右上メニュー `☰` の「ゴミ箱」から **30 日間・最大 30 件** まで個別復元・完全削除が可能です。


* **テンプレートとカテゴリ**：
* よく使う予定をテンプレートとして保存し、日付以外の項目を一括入力できます。
* カテゴリの追加・削除・並び替え・フィルタに対応。PC ではホイール・ドラッグ・`‹ ›` ボタンでカテゴリバーを横スクロールできます。
* **カテゴリ色・個別色**：36 色のパレットまたはカラーコードで指定可能（未指定時は自動割り当て）。ダークテーマ「墨」では色相を保ったまま視認しやすい明るさに自動補正します。
* **カテゴリ画像アイコン**：設定から PNG / JPEG / WebP / GIF を選択すると、端末内で 64px（約 8KB 以下）に縮小して同期します。フィルタ・カード・今週ビュー・テンプレート一覧・クイック入力プレビューに表示されます（Discord・メール・カレンダーには非表示）。


* **予定の重複警告と祝日判定**：
* 登録・編集時に時間帯が重なる他予定があると警告を表示します（登録自体はブロックしません）。期間つき予定は「開始〜締切」、単発予定は「締切 30 分前〜締切」で判定し、終日および複数日またぎの予定は対象外です。
* 2026〜2032 年の祝日データを内蔵し、休日に締切を設定した際に注意を促します。



### 2.2 4つの画面ビューと表示設定

画面は **一覧・今週・カレンダー・完了** の 4 タブ構成（スマホは画面下部固定、PC は見出し下）で、設定は右上のメニュー（`☰`）から開きます。

* **一覧ビュー**：
* **今日のサマリー**：上部に「今日締切・今日の定期予定・今日開始・7日以上の滞留」の件数を 1 行表示し、タップで該当画面へ移動します。
* **緊急度グループ**：期限切れ／今日／明日／今週／これから に自動分類。7 日以上放置された滞留項目は強調表示されます。
* **表示切り替えと検索**：「↻ 定期」で定期予定の次回分を一覧に混載できるほか、虫めがねアイコンからタイトル・メモの検索ができます。


* **超過一覧・定期予定一覧**：
* **超過一覧**：期限を過ぎた締切（完了忘れの定期予定を含む）を経過日数順に表示します。未完了の超過件数は一覧タブに赤いバッジで表示されます。
* **定期予定一覧**：繰り返し予定を毎週・隔週・毎月・毎年ごとに整理して確認できます。


* **今週ビューと日表示（タイムライン）**：
* 「今週」タブでは今日から 7 日間を縦に並べ、予定のない日も表示します。
* 今週タブの日付またはカレンダーの「時間軸で見る」から **0〜24 時の日表示** を開け、重複予定は横並び、終日・複数日期間は上部帯で表示されます。


* **月表示カレンダー**：
* 日付タップでその日の予定を表示。各マスの背景色は未完了締切の件数に応じて 3 段階に濃くなります。
* 右端の「週」列（日〜土区切り）に週間件数を表示し、**週 6 件以上**または**1 カテゴリ 3 件以上**の週には `⚠` を表示します。定期予定の帯は全体または予定ごとに非表示にできます。


* **レスポンシブ・オフライン・ショートカット**：
* 横幅 960px 以上の画面では一覧系カードを 2 列表示（端末設定で 1 列に変更可）、カレンダーは月表と選択日の予定を左右分割で表示します。
* Service Worker により一度開けばオフラインでも起動でき、対応環境ではアプリアイコン長押しから「締切を登録」「今週の予定」へ直接アクセスできます。



### 2.3 予定の種類

| 種類 | 説明 |
| --- | --- |
| **通常の締切** | 日時を指定する単発の締切 |
| **終日** | 時刻を指定しない締切。カレンダーにも終日予定として出力 |
| **期間つき** | 出張・研修など開始日と終了日を持つ予定。残り日数は「開始日まで」をカウント |
| **繰り返し** | 毎週・隔週・毎月・毎年（回数指定可）。`.ics` では `RRULE`、特定の回だけ休む場合は `EXDATE` で出力 |

### 2.4 WebClass 成績表 CSV の取り込み

右上メニュー `☰` →「データ」→「WebClass の CSV を取り込む」から、WebClass で書き出した成績表 CSV を一括取り込みできます。

* **自動判定とフィルタ**：期限切れ・提出済み・自習用・任意・授業以外・締切なし・締切が変更 のバッジ付きで候補を一覧表示します。初期状態では「未提出・今後の締切・必須課題」のみ自動選択され、絞り込み・検索・コース単位の一括選択が可能です。
* **重複と除外の管理**：選択した項目のみ「課題」カテゴリ（メモにコース名）として登録します。登録済み項目は次回以降スキップされ、WebClass 側で締切が変わった場合のみ「締切が変更」として更新候補に出ます。
* **除外リスト**：取り込まなかった項目やアプリ側で削除した項目は、教材名とコース名のハッシュのみを除外リストへ保存し次回以降非表示にします（ゴミ箱復元または除外リストリセットで解除可能、締切変更時は再表示）。
* **ローカル処理**：CSV ファイルは端末のブラウザ内のみで解析し、サーバーへは一切送信しません（実物 CSV は `.gitignore` で除外済み）。

### 2.5 端末間同期とデータ保護

* **Cloudflare 経由の双方向同期**：Worker から配信されたアプリでアクセスキーを設定すると、D1 上のデータと同期できます（版番号 `rev` で更新を判定）。
* **自動同期・自動取り込み**：
* 「Cloudflareへ自動で同期する」をオン（初期値オフ）にすると、登録・編集・完了・削除・延期・休み設定などの数秒後に自動送信します。
* アクセスキー保存済みかつ端末に未同期の変更がない場合、起動時・画面復帰時・10 分ごとに他端末の更新を自動反映します（端末側に未同期の変更がある場合は自動上書きせず通知）。


* **上書き事故の防止と警告**：最終同期から 1 日以上空くと警告を表示します。24 時間以上未取得の状態や他端末の新しい更新がある状態で手動同期すると確認ダイアログを挟み、同意後に**現在の内容を世代バックアップへ保存してから**上書きします。
* **破損データの隔離と修復**：同期データが一部破損していても正常な項目はそのまま利用でき、異常な項目のみ隔離されます。隔離された項目は設定画面から修復して一覧へ戻せます。

### 2.6 演出・テーマ・効果音

設定（右上メニュー `☰`）から端末ごとにカスタマイズできます（設定値は同期されません）。

* **テーマ**：**抹茶・石・墨** の 3 種類（ヘッダーの `◐` でも切替可）。未選択時は端末のダークモード設定に合わせて「墨」または「抹茶」を自動適用します。
* **演出モード**：**ゲーム風／手帳風／なし** から選択可能。画面遷移時は約 0.2 秒の軽いスライドアニメーションが入ります（「なし」または OS の「視差効果を減らす」有効時は停止）。
* **ゲーム風演出とレベルシステム**：
* 登録時に「クエスト受注！」、完了時に「ミッション達成！」の帯を表示し、期限内・前倒し完了ほど多くの EXP を獲得します（100 EXP ごとにレベルアップ）。
* その日の締切をすべて完了すると「本日のクエスト全クリア」（ボーナス +20 EXP、1 日 1 回）が発動します。
* ヘッダーに Lv・EXP ゲージ・連続日数を表示し、直近 7 日の達成マス（18 時以降未達なら「今日まだ」の赤枠、7 日連続で「皆勤」）が確認できます。完了ログと繰越 EXP は同期されるため、どの端末でも同じレベルが表示されます。


* **手帳風演出**：派手な帯を出さず、完了カードに朱色の「済」スタンプ、当日全完了時に「皆済」スタンプを押します（EXP・レベルの記録は共通）。
* **効果音（Web Audio API）**：音声ファイルを使わずブラウザ内でリアルタイム生成します（初期値「なし」、コンプレッサー内蔵）。
* **ゲーム風**：決定音のような弾む電子音（操作ごとに 0.2〜1.5 秒）。
* **手帳風**：完了のハンコ「ぺたっ」（1 日初回のみ鳴動、5 回ごとに朱肉「とんとん」）、全完了の「ぺたぺた…どん」、登録の鉛筆「カリカリ」、メモチェック・今日の一手の赤ペン「シュッ」、延期・休みの付箋「ぴたっ」、削除の紙丸め「くしゃっ」などの文具音に変化します。
* 夜間静音（22 時〜7 時）の仕組みも内蔵しています（初期値オフ）。

## 3. 通知・外部連携

* **iOS 標準カレンダー連携（`.ics`）**：
* 1 件ずつ／表示中まとめて／全件の `.ics` 書き出しに対応。
* 通知タイミングは設定画面のカテゴリ一覧から **14日前・7日前・3日前・2日前・前日・当日** を複数選択できます（既定は 7日前・前日・当日）。
* `FEED_TOKEN` を設定すると、メモを除いた購読用 URL（`/ics/<FEED_TOKEN>.ics`）を発行できます。


* **Discord 定期通知・即時送信**：
* 設定画面の「Discordへ今すぐ送信」から手動送信できるほか、Cloudflare の Cron で以下の定期通知を送ります。
* 見出し件数および負荷予報では「自動完了予定（締切経過で自動完了する項目）」を除外してカウントし、一覧には `N件＋自動完了M件` の形式で表示します。
* セキュリティ上の理由から、旧環境で行っていた `data.json` の Discord 添付は廃止しました。



| 通知種別 | 配信時刻（JST） | 内容 |
| --- | --- | --- |
| **朝の一覧** | 毎日 6:47 | 今日の一手・7日以上の滞留・期限切れ・今日締切・7日以内・定期予定。期限切れと今日締切の行に「✅完了」リンクを付与 |
| **夜の再通知** | 月〜土 20:23 | 期限切れと今日締切の未完了項目のみ送信（該当なしの場合は送信しない） |
| **週次レビュー** | 日曜 20:23 | 2 通に分割送信。① 来週 7 日間の見通しと今週の達成実績、② 定期予定の達成状況・2 週間の負荷予報（週 6 件以上または 1 カテゴリ 3 件以上で `⚠️`）・月初日曜のみ「サブスクなど」の月額換算集計 |

* **Gmail 連携・JSON 出力**：モーニングブリーフ用の定時メール送信、設定からの即時送信、JSON 形式での手動バックアップに対応しています。

## 4. iPhone ウィジェット（Scriptable）

### 4.1 締切ウィジェット

iPhone 内の購読カレンダー「締切トラッカー」をローカルで読み取ってホーム画面に表示します。スクリプト内に URL やアクセスキーを埋め込む必要はありません。

1. App Store で **Scriptable**（無料）をインストールします。
2. [`widgets/scriptable/deadlines.js`](widgets/scriptable/deadlines.js) のコードをコピーし、Scriptable で新規スクリプトを作成して貼り付けます。
3. スクリプトを一度実行し、**カレンダーへのアクセス**を許可します。
4. ホーム画面に Scriptable ウィジェットを追加し、作成したスクリプトを選択します。
5. ウィジェットの **Parameter** にアプリの URL を入力すると、タップでアプリを起動できます（空欄でも表示は動作します）。

* **表示仕様**：小 5 件・中 6 件・大 16 件まで表示し、超過分は末尾に「ほかN件」と表示します。超過は赤（`超過N日`）、当日は橙（`今日`）、2〜6 日先は曜日、7 日以上は `8/12(水)` 形式で表示します。
* **注意点**：表示の更新は iOS の購読カレンダー同期間隔（目安 1 時間）に依存します。購読 `.ics` の仕様上、メモとカテゴリは表示されません。

### 4.2 AI の使用量ウィジェット

Codex・Muse の使用率とリセット時刻、Claude Code のログイン期限を表示します（Worker の `GET /api/usage` を使用）。

1. 24 文字以上のランダムなトークンを作成し、Cloudflare Worker のシークレット `USAGE_TOKEN` に登録します（**`APP_KEY` とは必ず別の値**にしてください）。
2. 同じトークンを Muse の vault にも登録します。
3. `widgets/scriptable/usage.js` を Scriptable に貼り付けて一度実行し、トークンを入力します。
4. ウィジェットの **Parameter** にアプリの URL を設定し、中サイズのウィジェットを配置します。
* トークンを更新する際は、Worker と vault を更新したうえで Scriptable 内でスクリプトを実行し、「トークンを入れ直す」から新しい値を保存してください。

## 5. セットアップ手順

### Step 1：Cloudflare Worker と D1 を作成する

1. Cloudflare の **Workers & Pages** でこのリポジトリ（`main` ブランチ）を GitHub 連携（Workers Builds）し、Worker `deadline-tracker` を作成します（設定は `wrangler.jsonc` を参照）。
2. D1 データベースを作成し、`wrangler.jsonc` の `d1_databases` 内にある `database_id` を自分の ID に書き換えます（テーブルは初回リクエスト時に自動作成されます）。
3. Worker のシークレットに `APP_KEY`（24 文字以上のランダム文字列）を登録します。
4. `https://<Worker名>.<サブドメイン>.workers.dev/` にアクセスし、`GET /api/health` が `{"ok":true}` を返すことを確認します。
* iPhone では Safari の共有ボタン →「ホーム画面に追加」でアプリとして利用でき、この時点で締切管理と `.ics` 書き出しがすべて使えます。



### Step 2：端末をつないで同期する

1. アプリ右上のメニュー（`☰`）→「端末間の同期」に `APP_KEY` を入力します。個人端末では「この端末にアクセスキーを保存」にチェックを入れると暗号化して保存されます（共用端末では保存しないでください）。
2. 空の端末にキーを入力すると、D1 から自動でデータを読み込みます。以降の起動時・画面復帰時は最大 4 秒間「読み込み中」の帯を出して最新データを取得します（オフライン時は「圏外のため前回の内容」として編集・送信待ちキューに蓄積）。
3. 必要に応じて「Cloudflareへ自動で同期する」をオンにします。
* **認証エラー保護**：アクセスキーが不一致（`401`）になった端末は自動通信を停止し、一度だけ通知を出します（同一回線の他端末が IP 制限に巻き込まれるのを防ぐため）。キーを再入力すると再開します。



### Step 3：Discord と Gmail を連携する（任意）

シークレットを登録するまで外部送信は一切行われません。

* **Discord**：対象チャンネルの「連携サービス」→「ウェブフック」で URL を発行し、シークレット `DISCORD_WEBHOOK_URL`（および任意で `DISCORD_USER_ID`・`APP_URL`）に登録します。
* **Gmail**：Google Cloud で OAuth クライアントを作成し、`gmail.send` スコープのみのリフレッシュトークンを取得して `GOOGLE_*` と `MAIL_TO` に登録します（OAuth 同意画面は必ず「本番」にしてください。「テスト」のままだと 7 日で失効します。詳細は `docs/cloudflare-migration.md` を参照）。
* **動作確認**：設定画面の「Discordへ今すぐ送信」または `GET /api/digest`・`GET /api/mail` で文面を確認できます。

### Step 4：アプリ内の初期設定

右上メニュー（`☰`）から、当日リマインド時刻・カテゴリ・テーマ・演出・効果音を設定します。また「バージョン確認」から表示中の版とサーバー上の版を比較できます（版番号ルールは [docs/VERSIONS.md](docs/VERSIONS.md)）。

### Cloudflare のシークレット一覧

設定値はすべて Worker の「設定 → 変数とシークレット」から種類を **「シークレット」** にして登録してください（「変数」で登録するとデプロイ時に消える場合があります）。**値をリポジトリやログに書き残さないでください。**

| シークレット名 | 用途 | 必須 | 未設定時の挙動 |
| --- | --- | --- | --- |
| `APP_KEY` | アプリ・API 認証用アクセスキー（24 文字以上のランダム値） | **必須** | API が `503` で停止 |
| `USAGE_TOKEN` | `/api/usage` 専用トークン（`APP_KEY` と別値必須） | 使用量連携時 | `/api/usage` が `503` |
| `FEED_TOKEN` | 購読用 `.ics` の URL トークン（24 文字以上、`APP_KEY` と別値） | 任意 | `/ics/…` が `404` |
| `DISCORD_WEBHOOK_URL` | Discord 通知先の Webhook URL | 任意 | Discord 通知を送らない |
| `DISCORD_USER_ID` | 通知冒頭でメンションする Discord ユーザー ID | 任意 | メンションなし |
| `APP_URL` | 通知内のリンク（「アプリを開く」「✅完了」）に使う URL | 任意 | リンクを出さない |
| `DONE_LINKS` | `0` を指定すると「✅完了」リンクを非表示 | 任意 | リンクを付与する |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REFRESH_TOKEN` | Gmail API（`gmail.send`）認証情報 | 任意 | メールを送らない |
| `MAIL_TO` | 通知メールの宛先（自分のアドレス） | 任意 | メールを送らない |
| `MAIL_FROM` | 通知メールの送信元アドレス | 任意 | `MAIL_TO` と同じ値を使用 |

## 6. 運用・メンテナンス・トラブルシューティング

### 6.1 バックアップと復元

データは Cloudflare D1 に保存され、端末の `localStorage` にキャッシュされます。

| 手段 | 保存タイミング | 保持・間引きルール |
| --- | --- | --- |
| **世代バックアップ（D1）** | 保存時、前回から 30 分以上経過していれば上書き前のデータを自動保存（`?force=1`・`?backup=1`・確認同意時の上書きでは必ず保存） | 毎日 5:23 に自動整理：直近 14 日は全件、15〜90 日は週 1 件、それ以前は月 1 件を保持 |
| **JSON 書き出し** | 右上メニュー `☰` →「JSONで書き出す」で手動保存 | 端末側に任意保存 |

#### アプリから世代バックアップを復元する

1. 右上メニュー `☰` →「バックアップと復元」→「世代バックアップの一覧を読み込む」を押します。
2. 日時・版番号・サイズ順に一覧が表示されるので、復元したい世代の「中身」で件数と先頭 5 件を確認します。
3. 「この時点に戻す」を実行します。**復元直前の状態も自動で新しい世代バックアップに残る**ため、戻しすぎてもやり直せます。

#### API から手動復元する（アプリが開けない場合）

1. バックアップ一覧を取得し、対象世代の `id` を確認します。
```bash
curl -H "Authorization: Bearer $APP_KEY" https://<Worker>/api/snapshots

```


2. 該当 `id` のデータを取得し、レスポンス内の `data` オブジェクトだけを `restore.json` として保存します。
```bash
curl -H "Authorization: Bearer $APP_KEY" https://<Worker>/api/snapshots/<id>

```


3. アプリの「JSONを読み込む」で端末に反映したあと、「同期」を押して「バックアップ付きで上書き」を選択します。

> **復元の練習手順**：本番データが正常なうちに、① JSON 手動書き出し → ② 1 つ前の世代へ復元 → ③ 件数や他端末の同期を確認 → ④ 先頭の世代（直前の状態）へ戻す、という手順を試しておくと安心です。結果は `docs/IMPROVEMENTS.md` の項目 36 に件数と日時のみ記録してください（締切の題名やメモは書かないこと）。

### 6.2 D1 本体の障害復旧（Time Travel）

D1 データベース自体が破損・消失した場合は、追加費用なしで常時有効な **Cloudflare D1 Time Travel** で過去時点へ巻き戻せます（保持期間：Free プラン **7 日**／有料プラン **30 日**）。

```bash
# 現在のブックマークを確認
npx wrangler d1 time-travel info <データベース名>

# 指定時刻へ復元（実行中の処理は中断され、その場で上書き）
npx wrangler d1 time-travel restore <データベース名> --timestamp=<UNIX秒 8601 ISO または>

```

復元直後に表示される「前のブックマーク」を控えておけば、`--bookmark=<前のブックマーク>` で復元操作自体を取り消せます。7 日より前には戻せないため、月 1 回程度の JSON 書き出しも推奨します。

### 6.3 アクセスキー（`APP_KEY`）・購読 URL（`FEED_TOKEN`）の入れ替え

* **`APP_KEY` の変更**：Cloudflare 側で新しい 24 文字以上のシークレットを保存・デプロイしたあと、各端末の設定画面で新しいキーを入れ直します（キーを変えても D1 内のデータは失われません）。
* **`FEED_TOKEN` の変更（URL 漏洩時）**：
1. `openssl rand -base64 24 | tr -d '/+='` 等で新しいトークンを生成し、Cloudflare の `FEED_TOKEN` を上書きデプロイします。
2. 旧 URL（`https://<Worker>/ics/<旧トークン>.ics`）が `404` になることを確認します。
3. 各端末のカレンダーアプリから**古い照会カレンダーを必ず削除**し、アプリ設定の「カレンダーで購読する」から新しい URL を登録し直します（古い購読が残ると同名カレンダーが重複し、Scriptable ウィジェットが古い方を参照する原因になります）。



### 6.4 祝日データの更新

`app.js` 内の `HOLIDAYS` に **2026〜2032 年** の祝日を直書きしています。収録期間を過ぎる前、または法改正・振替休日の変更があった場合は、[holiday_jp](https://github.com/holiday-jp/holiday_jp) の `holidays.yml` を参照して年 1 回を目安に更新してください。

### 6.5 既知の注意点

* **iPhone で `.ics` を取り込む際の注意**：Discord などの添付ファイルを直接タップすると、iOS が「照会カレンダー」として登録してしまい変更が反映されません。通知内の「カレンダーに入れる」リンクから開くか、ファイルを長押し →「ファイルに保存」してから開いてください。
* **日本時間（JST）前提**：アプリは端末時刻、Worker は日本時間で日付を計算します。海外渡航などで端末のタイムゾーンが変わると日付判定が 1 日ずれる場合があります。
* **繰り返し予定の編集場所**：カレンダー画面に表示される繰り返しの回は表示用複製のため、「この回は休み」のみ操作できます。本体の編集・完了は「定期予定」一覧から行ってください。
* **同期は全体上書き方式**：項目単位の差分マージは行いません。他端末の更新がある場合は「読み込み」または「バックアップ付き上書き」を選択します。
* **アクセスキー暗号化と厳格な CSP**：
* 保存されたアクセスキーは、IndexedDB 上に生成した取り出し不能な鍵（WebCrypto `extractable: false`）で暗号化し、暗号文のみを `localStorage` に保存します（WebCrypto 非対応環境では平文保存せず都度入力となります）。
* XSS 対策として厳格な CSP（`script-src 'self'`、`style-src-attr 'none'`）を適用しており、HTML 内のインラインスクリプトや `style="..."` 属性は使用していません（動的なスタイルは `data-st` 属性経由で CSSOM から適用）。

### API エンドポイント一覧

`GET /api/health` と `GET /ics/<FEED_TOKEN>.ics` を除き、すべて `Authorization: Bearer <キー>` ヘッダが必要です。認証失敗が連続した IP は 10 分間ブロックされます（正しいキーで認証すると即座に解除）。

| メソッド・パス | 概要 |
| --- | --- |
| `GET /api/health` | ヘルスチェック（認証不要） |
| `GET /api/data` | 締切データと現在の版番号（`rev`）を取得 |
| `PUT /api/data` | 締切データを保存。`If-Match: <rev>` 不一致時は `409`、`?force=1` で強制上書き、`?backup=1` で必ず世代保存。タイトル空・存在しない日付・範囲外数値・`start > due` は `400` |
| `GET /api/usage` | AI 使用量を取得（`USAGE_TOKEN` 認証） |
| `PUT /api/usage` | AI 使用量を保存（`v: 1` および `codex` / `muse` / `claudeCode`、最大 4KB） |
| `GET /api/snapshots` | 世代バックアップ一覧を取得（新しい順に最大 200 件） |
| `GET /api/snapshots/<id>` | 指定 ID の世代バックアップ内容を取得 |
| `GET /api/feed` | 未完了の締切一覧を取得（`?days=14`） |
| `GET /api/ics` | `.ics` 出力（`?memo=0` でメモ除外、`?dayHour=9` で当日リマインド時刻指定） |
| `GET /ics/<FEED_TOKEN>.ics` | 購読用 `.ics`（メモなし・1 時間更新指定、URL トークン認証） |
| `GET /api/feed-url` | 設定済みの `FEED_TOKEN` から購読用 URL を組み立てて返す |
| `GET /api/mail` / `POST /api/mail` | 締切メールのプレビュー生成（`GET`）／即時送信（`POST`）。`?target=today|tomorrow|auto` |
| `GET /api/digest` / `POST /api/digest` | Discord 通知文面のプレビュー生成（`GET`）／即時送信（`POST`）。`?kind=morning|evening|weekly` |
| `GET /api/notify-log` | 定期通知の最新成功時刻と直近 7 日間の失敗履歴を取得 |

### 定時処理（Cron Triggers）

Cron は UTC 指定（`UTC = JST - 9時間`）です。同一トリガー内の処理が一部失敗しても残りを続行し、最後にまとめてエラー報告します。

| Cron（UTC） | 日本時間（JST） | 実行内容 |
| --- | --- | --- |
| `47 21 * * *` | 毎日 6:47 | 朝の締切一覧を Discord へ送信 |
| `23 11 * * *` | 毎日 20:23 | 翌日分の締切メールを Gmail へ送信 ＋ 月〜土は夜の再通知、日曜は週次レビューを Discord へ送信 |
| `23 20 * * *` | 毎日 5:23 | 当日分の締切メールを Gmail へ送信 ＋ 世代バックアップの間引きと古いログの掃除 |

* **重複防止と未達検知**：Cron 実行結果は D1 の `notify_log` に記録し（30 日保持）、同日の二重送信を防止します。送信失敗があった場合は直近 7 日分を次回の Discord 通知末尾に 1 行で追記（`⚠️ 届いていない通知：11/8 夜の再通知`）するほか、アプリ設定の「前回届いた日時を確かめる」からも確認できます（手動 `POST` は記録対象外）。
* **メール件名**：外部ルーティンでの検索用に「`【締切トラッカー】M/D（曜）の締切`」で固定しています。

### URL パラメータ

* `?export=all|once|rep`：起動時に `.ics` を自動ダウンロードします（`all`: 未完了全件、`once`: 繰り返しを除く締切のみ、`rep`: 定期予定のみ）。
* `?done=<締切ID>`：クラウドから最新状態を取得（最大 4 秒）したうえで完了確認ダイアログを表示し、承認後に完了処理（定期予定は次回へ進行）を行います。処理後にパラメータを URL から除去するため、再読み込みによる二重完了は起きません。

### GitHub Actions によるマージ通知メール

`main` への PR マージ時、`.github/workflows/merge-mail.yml`（`.github/scripts/send_merge_mail.py`）が変更概要を Gmail へ自動送信します（件名：`【deadline-tracker】#番号 タイトル をマージしました`）。利用する場合はリポジトリの Secrets に `GMAIL_ADDRESS` と `GMAIL_APP_PASSWORD` を登録してください。
