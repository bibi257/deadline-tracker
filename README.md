# 締切トラッカー

仕事や生活の締切を登録して、**iPhoneのカレンダー通知**と**Discordへの毎朝の連絡**に流すための、サーバー不要な個人用Webアプリ。

GitHub Pages で動く単一のHTMLファイルで、ランニングコストは0円。

```
締切を登録
   ├─→ .ics を書き出す ──→ iOS標準カレンダー（1週間前・前日・当日に通知）
   └─→ GitHubに同期  ──→ GitHub Actions（毎朝、Discordへ一覧を送信）
```

---

## 設計の考え方

**通知は他のアプリに任せる**

静的サイトはページを閉じている間に通知を出せない。そこで通知だけを外部に委譲している。確実に鳴らしたいものは iOS カレンダーへ、毎日ざっと確認したいものは Discord へ。アプリ自身は「締切の管理と見える化」に徹する。

**締切と定期予定を分ける**

定例会議のような繰り返しの予定が締切リストに混ざると、本当に期限のあるタスクが埋もれる。タブを分け、カレンダー上も色で区別する。

**残り日数が主役**

一覧では残り日数を大きく表示し、経過メーターで締切までの進み具合を示す。期限切れ・当日・3日以内・7日以内で色が変わる。

## 機能

### 締切の管理

- 登録・編集・削除・完了（完了分はアーカイブへ）
- 残り日数の表示、経過メーター、緊急度による色分け
- 期限切れ／今日／明日／今週／これから のグループ表示
- 月表示カレンダー（日付をタップでその日の予定）
- カテゴリの追加・削除・並び替えと、カテゴリ別フィルタ
- テンプレート（よく使う締切の雛形。締切日は「今日から◯日後」で計算）
- 今週ビュー（今日から7日分を縦に並べ、予定のない日も表示）
- 祝日表示（2026〜2032年収録）と、休日に締切を設定したときの注意
- 滞留の警告（7日以上放置された項目を強調し、通知の冒頭にも出す）

### 予定の種類

| 種類 | 説明 |
|---|---|
| 通常の締切 | 日時を指定 |
| 終日 | 時刻を決めない。カレンダーにも終日予定として入る |
| 期間つき | 出張・研修期間など。残り日数は「開始日まで」を数える |
| 繰り返し | 毎週・隔週・毎月・毎年。回数指定も可能。特定の回だけ取りやめられる |

### 通知・連携

- `.ics` 書き出し（1件ずつ／表示中まとめて／全件）。繰り返しは RRULE、取りやめた回は EXDATE で表現
- 通知は「1週間前・前日・当日の指定時刻」の3件。繰り返し予定でも毎回鳴る
- Discord への毎朝のダイジェスト送信（GitHub Actions）
- 設定タブから Discord へ即時送信
- GitHub 経由の端末間同期（送信・受信の両方向）
- JSON でのバックアップと復元
- ダークモード、レスポンシブ表示、ホーム画面追加用アイコン
- オフライン起動（Service Worker）。一度開いておけば圏外でも画面が開く
- 設定タブでバージョン確認（表示中の版とサーバー上の版を比較）
- 削除の取り消し（直前の1件のみ、トーストから「元に戻す」）
- 一覧タブでのタイトル・メモ検索

## 構成

リポジトリを2つに分けている。締切の内容が他人に見えないよう、**データは必ず Private 側に置く**。

```
deadline-tracker（Public / GitHub Pages で公開）
├── index.html              アプリ本体（HTML/CSS/JS をすべて内包）
├── manifest.webmanifest    ホーム画面追加用の設定
├── service-worker.js       オフライン起動用
├── assets/
│   └── icon-180/192/512.png    アイコン
└── deadline-data-template/     Private側に置くファイルの雛形（設定は空。使い方は同梱のREADME）

deadline-data（Private / データと自動送信）
├── data.json                           締切データ（アプリから自動生成・更新）
└── .github/
    ├── workflows/daily-digest.yml      毎朝の実行スケジュール
    └── scripts/
        ├── send_digest.sh              Discordへ送る処理（設定はこの冒頭）
        └── build_ics.py                添付する .ics を作る処理
```

Public リポジトリはファイル一覧もコミット履歴も公開される。ファイル名を変えたり深い階層に置いても隠したことにはならないため、リポジトリの分離が唯一の確実な方法になる。

### 技術構成

| 要素 | 内容 |
|---|---|
| ホスティング | GitHub Pages |
| フロントエンド | HTML / CSS / JavaScript（フレームワークなし・単一ファイル） |
| データ保存 | localStorage ＋ GitHub Contents API による同期 |
| 定期実行 | GitHub Actions（cron） |
| 費用 | 0円 |

## セットアップ

### 1. アプリを公開する

1. `index.html`・`manifest.webmanifest`・`service-worker.js`・`assets/` フォルダを、自分の Public リポジトリにアップロードする
2. **Settings → Pages** を開き、Source を `Deploy from a branch`、Branch を `main / (root)` にして Save
3. 1〜2分待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で開く

iPhone では Safari で開いて共有ボタン →「ホーム画面に追加」でアプリのように使える。

ここまでで、締切の管理と `.ics` の書き出しは使える。以降は任意の機能。

### 2. 端末間で同期する

1. Private リポジトリ（例：`deadline-data`）を新規作成する
2. **Settings（アカウント） → Developer settings → Fine-grained tokens** でトークンを発行する
   - Repository access: 作成した Private リポジトリのみ
   - Permissions: **Contents → Read and write**
3. アプリの **設定タブ → 端末間の同期とDiscord通知** に、ユーザー名・リポジトリ名・トークンを入力する
4. **GitHubに同期する** で送信、別の端末では **GitHubから読み込む** で受信

> 読み込むと、その端末のデータは GitHub 上の内容で**置き換わる**（実行前に確認が出る）。両方の端末で別々に編集してから読み込むと片方が消えるため、「登録するのは主に1台、他は読み込むだけ」という使い方が安全。

### 3. Discord へ毎朝の連絡を送る

1. Discord のチャンネル設定 →「連携サービス」→「ウェブフック」で URL を取得する
2. Private リポジトリに `.github/workflows/daily-digest.yml` と `.github/scripts/`（`send_digest.sh`・`build_ics.py`）を配置する
   - **`deadline-data-template/` の中身をそのままコピーすればよい**（設定値は空にしてある）
   - GitHub 上で **Add file → Create new file** を選び、ファイル名にスラッシュを含めて入力するとフォルダごと作られる
   - ワークフロー内の `run:` のパスと、スクリプトの実際の置き場所を一致させること
3. `send_digest.sh` の冒頭に Webhook URL などを記入する
4. Private リポジトリの **Actions** タブ → **Run workflow** で動作を確認する

> ⚠️ Webhook URL をスクリプトに直接書くため、**このファイルは必ず Private リポジトリに置くこと**。万一漏れた場合は Discord 側でウェブフックを削除すれば即座に無効化できる。Public に置きたい場合は、リポジトリの Secrets に登録して環境変数から読ませる（環境変数がスクリプト内の値より優先される）。

## 設定項目

### `.github/scripts/send_digest.sh` の冒頭

```bash
DEFAULT_WEBHOOK_URL="https://discord.com/api/webhooks/..."   # 通知先
MENTION_USER_ID="000000000000000000"                         # 空にするとメンションしない
DEFAULT_WINDOW_DAYS="7"                                      # 何日以内を対象にするか
BACKUP_DOW="1"                                               # data.json を添付する曜日（1=月, 0=しない）
APP_URL="https://<ユーザー名>.github.io/<リポジトリ名>/"      # 通知に載せるアプリのリンク
ATTACH_ICS="0"                                               # .ics を添付するか（既定0）
ICS_DAY_HOUR="9"                                             # .ics 内の当日リマインド時刻
```

### `.github/workflows/daily-digest.yml`

```yaml
- cron: "47 21 * * *"   # UTC 21:47 = JST 6:47
```

cron は UTC 基準（`UTC = JST − 9時間`）。GitHub の cron は混雑時に遅れるため、「0分ちょうど」を避けると比較的安定する。数十分の遅延は仕様上ありうるので、「朝のうちに届けばよい」程度の想定で使う。

### アプリ内（設定タブ）

当日リマインドの時刻、カテゴリ、テーマ（自動・ライト・ダーク）を変更できる。

## URLパラメータ

`?export=` を付けて開くと、`.ics` の書き出しが自動で始まる。

| 値 | 対象 |
|---|---|
| `all` | 未完了の全件 |
| `once` | 締切のみ（繰り返しを除く） |
| `rep` | 定期予定のみ |

Discord の毎朝の通知には `?export=all` のリンクが載る。

---

## データとバックアップ

保存先はブラウザの localStorage で、端末ごとに独立している。復元手段は3つある。

| 手段 | 作られるタイミング | 復元方法 |
|---|---|---|
| GitHub のコミット履歴 | 同期のたび | `data.json` → History から任意の時点を取得 |
| Discord への週次添付 | 毎週月曜の朝 | 添付を保存 → 設定タブの「JSONを読み込む」 |
| 手動の JSON 書き出し | 任意 | 同上 |

最も細かく戻せるのはコミット履歴。

## 祝日データの更新

`index.html` 内の `HOLIDAYS` に 2026〜2032年分を直書きしている。通信不要でオフラインでも動く代わりに、**収録範囲を過ぎたら手動で更新が必要**。

出典は [holiday_jp](https://github.com/holiday-jp/holiday_jp)（内閣府「国民の祝日について」を元にしたデータ）。同リポジトリの `holidays.yml` から必要な年を抜き出して置き換える。法改正や振替で変わることがあるため、年に一度は確認するとよい。

## 既知の注意点

**iPhone でカレンダーに取り込むとき**

Discord などの添付ファイルを直接タップすると、iOS は「照会カレンダー」として登録してしまい、更新がすぐ反映されない。通知内の「カレンダーに入れる」リンクから開くか、添付を長押し →「ファイルに保存」してから開くこと。

**繰り返し予定の編集**

カレンダー画面に並ぶ繰り返しの回は表示用の複製のため、完了・編集は「定期予定」タブから行う。カレンダーからは「この回は休み」のみ操作できる。

**同期は上書き**

差分のマージは行わない。詳細は「2. 端末間で同期する」の注記を参照。
