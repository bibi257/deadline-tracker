# 締切トラッカー

仕事や生活の締切を登録して、**iPhoneのカレンダー通知**と**Discordへの連絡**に流すための、個人用Webアプリ。利用者は自分1人。

画面は静的なWebアプリ（HTML 1枚＋JavaScript 1本）で、保管と通知は **Cloudflare Workers + D1**（Worker 1つと小さなデータベース）が受け持つ。Cloudflare の無料枠で動くので、ランニングコストは0円。

```
アプリ（Worker から配信） ──→ Worker の API ──→ D1（締切データ・世代バックアップ）
  ├─ 締切を登録・編集             │
  ├─ .ics を書き出す ──→ iOS標準カレンダー（カテゴリごとに決めた日数前・当日に通知）
  └─ アクセスキーで同期           ├─ Cron ──→ Discord（朝・夜の再通知・日曜は週次レビュー）
                                  ├─ Cron ──→ 自分宛ての Gmail（モーニングブリーフ用）
                                  └─ /ics/<トークン>.ics ──→ カレンダーの購読（メモなし）
```

> GitHub Pages ＋ 非公開リポジトリ `deadline-data` ＋ GitHub Actions の旧環境は、移行が終わるまで残している。説明は「旧環境」の節にまとめた。移行の計画と進捗は `docs/cloudflare-migration.md`。

## 設計の考え方

**通知は他のアプリに任せる**

静的サイトはページを閉じている間に通知を出せない。そこで通知だけを外部に委譲している。確実に鳴らしたいものは iOS カレンダーへ、毎日ざっと確認したいものは Discord へ。アプリ自身は「締切の管理と見える化」に徹する。

**締切と定期予定を分ける**

定例会議のような繰り返しの予定が締切リストに混ざると、本当に期限のあるタスクが埋もれる。タブを分け、カレンダー上も色で区別する。

**残り日数が主役**

一覧では残り日数を大きく表示し、経過メーター（カードの下の線）で締切までの進み具合を示す。メーターは、繰り返さない予定では「登録した日から締切まで」、繰り返す予定では「前の回から次の回まで」（毎週なら7日の中での位置）。期限切れ・当日・3日以内・7日以内で色が変わる。

## 機能

### 締切の管理

- 登録・編集・削除・完了（完了分はアーカイブへ）
- 1行クイック入力（一覧の上部。「明日 17時 レポート提出」「毎週水曜 17:00 バイト #バイト」のように打つと、
  日時・繰り返し・カテゴリを読み取って登録画面を下書き状態で開く。テンプレート名だけ打つとテンプレートを使う。
  対応する書き方は入力欄の下「書き方の例」に一覧がある）
- 今日のサマリー（一覧の上部に1行。今日が締切・今日の定期予定・今日から始まる予定・7日以上の滞留の件数。
  数字を押すとその画面へ移り、「予定」で今日の予定の一覧を開く）
- 日表示（今週タブの日付、またはカレンダーの「時間軸で見る」から。0〜24時の時間軸に予定を並べ、重なる予定は横に並べる。
  終日と数日にまたがる期間は上部に帯で表示）
- 予定の重複の注意（登録・編集時、同じ時間帯に他の予定があれば知らせる。登録は妨げない）
  ※時間帯は .ics と同じく「期間つきは開始〜締切、それ以外は締切の30分前〜締切」とみなす。終日と数日にまたがる期間は対象外
- カテゴリごとの通知（設定（右上の歯車）のカテゴリ一覧で、.ics の通知を 14日前・7日前・3日前・2日前・前日・当日 から選ぶ。既定は 7日前・前日・当日）
- 残り日数の表示、経過メーター、緊急度による色分け
- 期限切れ／今日／明日／今週／これから のグループ表示
- 月表示カレンダー（日付をタップでその日の予定）。マスはその日の未完了の締切の数で3段階に濃くなり、右端の「週」の列に週の件数を出す。
  週6件以上か1カテゴリ3件以上の週は ⚠（週次レビューの負荷予報と同じ閾値。こちらは日〜土で区切る）
- カテゴリの追加・削除・並び替えと、カテゴリ別フィルタ
- テンプレート（よく使う締切の雛形。日付以外の項目が埋まる）
- 今週ビュー（今日から7日分を縦に並べ、予定のない日も表示）
- 超過の一覧（期限を過ぎたものだけを経過日数順に。完了にし忘れた定期予定の回も含む。
  一覧の「期限切れ」の見出し、またはサマリーの「滞留」から開く。件数は一覧タブに赤いバッジで出る）
- 定期予定の一覧（繰り返しの締切を毎週・隔週・毎月・毎年に分けて並べる。一覧の末尾のリンク、またはサマリーの「定期」から開く）
- 画面のタブは 一覧・今週・カレンダー・完了 の4つ。スマホでは画面の下に固定し、広い画面では見出しの下に並べる。設定は右上の歯車から
- 960px以上の画面では、一覧・超過・定期予定・完了のカードを2列に並べ（設定の「広い画面の並び」で1列にもできる。端末ごとの設定で同期しない）、カレンダーは月の表と選んだ日の予定を左右に並べる（今週・設定はこれまでの幅）
- 締切カードの操作は「完了にする」と「…」。カレンダーへ・編集・雛形に保存・削除（期限切れなら明日に延期、繰り返しならこの回は休み）は「…」の中
- 期限切れの「明日に延期」（締切を翌日の同じ時刻へ。トーストから元に戻せる）
- 同期の説明は、Cloudflare（Worker から配信したアプリ）と旧環境（GitHub）の両方に当てはまる。違いは「保存先」と「他の端末の更新の見分け方」（Cloudflare は版番号 `rev`、GitHub は更新時刻）
- 最終同期時刻の表示（1日以上空くと警告。同期し忘れに気づける）
- 上書き事故の防止（GitHubの内容を24時間以上取得していない状態や、他の端末の新しい内容を
  まだ読み込んでいない状態で同期しようとすると確認を挟み、同意すると `backups/` に現在の内容を
  自動保存してから上書きする。自動同期はこの場合は上書きせずに止まる）
- 自動同期の対象を拡大（登録・編集に加え、完了・削除・延期・休みの設定なども数秒後にまとめて同期）
- 他端末の更新を自動で取り込む（この端末に未同期の変更が無いときに限り、起動時・画面復帰時・
  10分ごとにGitHub上の新しい内容を自動反映。この端末で先に変更していた場合は自動上書きせず、
  一度だけ通知する）
- Publicリポジトリへの同期を警告（締切の内容が世界に公開される事故を防ぐ。一度確認したリポジトリは再警告しない）
- ゴミ箱（削除した締切を30日間保持。最大30件。設定（右上の歯車）から個別に復元・完全削除できる）
- 読み込みデータの検証（GitHub上のdata.jsonが壊れていても、正常な項目はそのまま使え、
  壊れた項目だけ隔離される。隔離項目は設定（右上の歯車）から修復して一覧に戻せる）
- 週次レビュー通知（毎週日曜夜、Discordへ。来週7日間の見通しと1週間の達成、続けて繰り返しの調子・
  2週間の負荷予報・月初めは「サブスクなど」の支出まとめ。詳しくは「通知・連携」）
- ホーム画面ショートカット（対応環境でアイコン長押し →「締切を登録」「今週の予定」に直行）
- 祝日表示（2026〜2032年収録）と、休日に締切を設定したときの注意
- 滞留の警告（7日以上放置された項目を強調し、通知の冒頭にも出す）
- カテゴリごとの色（36色のテンプレートかカラーコードで指定。未指定は自動で割り振り。締切ごとの個別色も可。
  ダークモードでは色相を保ったまま明るさを補正）
- 一覧に定期予定の次の回も並べる（一覧の「↻ 定期」）／カレンダーの定期予定の帯を表示するか選ぶ（どちらも端末ごとの表示設定。
  帯は繰り返しの締切ごとにも隠せる）
- カテゴリの列はパソコンでも横に動かせる（ホイール・ドラッグ・‹ › ボタン）

### ゲーム風の演出（登録・完了）

- 登録すると「クエスト受注！」、完了すると「ミッション達成！」の帯を出し、期限内・前倒しほど多い EXP を得る（100 EXP ごとにレベルアップ）
- 今日が締切のものを全部片付けると「本日のクエスト全クリア」（ボーナス +20 EXP、1日1回）。ヘッダーに Lv・EXPゲージ・連続日数を表示。
  連続日数には直近7日のマスを付け、自分で完了にした日を塗る（右端の点線が今日。18時を過ぎてまだなら「今日まだ」と赤枠。7日すべて埋まると「皆勤」の印）
- 完了の記録（締切の何時間前か・前倒し／期限内／遅れ／自動・獲得EXP）と繰越 EXP は `data.json` に入り、端末間で同期される。
  どの端末でも同じレベルになり、Discord の週次レビューの集計にも使われる
- 設定（右上の歯車）で演出を「ゲーム風」「手帳風」「なし」から選べる。手帳風は帯を出さず、完了したカードに朱色の「済」の印を押し、
  今日の締切を全部片付けた日は「皆済」の印を出す（EXP・レベルの記録は同じ）。視差効果を減らす設定の端末では、動く演出も止まる
- 画面を切り替えると、中身が右から少しだけ滑り込んで表示される（約0.2秒）。酔わないよう、どの画面へ移っても向きは同じで、動く距離は小さい。
  演出「なし」・視差効果を減らす設定では動かない
- 効果音（登録・完了・削除・画面の切り替え）。Web Audio API でその場で作る音（登録・完了・削除は余韻を含めて約1〜1.5秒、画面の切り替えは約0.2秒の小さな音。手帳風では紙をめくる音）で、音声ファイルは使わない。設定（右上の歯車）の「効果音」で あり／なし（初めは なし、端末ごとの設定で同期しない）。演出の設定や「視差効果を減らす」とは独立

### 予定の種類

| 種類 | 説明 |
|---|---|
| 通常の締切 | 日時を指定 |
| 終日 | 時刻を決めない。カレンダーにも終日予定として入る |
| 期間つき | 出張・研修期間など。残り日数は「開始日まで」を数える |
| 繰り返し | 毎週・隔週・毎月・毎年。回数指定も可能。特定の回だけ取りやめられる |

### 通知・連携

- `.ics` 書き出し（1件ずつ／表示中まとめて／全件）。繰り返しは RRULE、取りやめた回は EXDATE で表現
- 通知は設定（右上の歯車）のカテゴリごとの日数（既定は7日前・前日・当日の指定時刻）。繰り返し予定でも毎回鳴る
- Discord への定期通知（Cloudflare の Cron。「定時の処理」）。下表
- 設定（右上の歯車）から Discord へ即時送信
- 通知の「✅完了」リンクから完了にする（`?done=`。確認を出してから完了にする）
- 端末間の同期（Cloudflare。旧環境では GitHub 経由。送信・受信の両方向）
- モーニングブリーフ用の連携（任意。下の「任意の追加機能」）
- JSON でのバックアップと復元
- ダークモード、レスポンシブ表示、ホーム画面追加用アイコン
- オフライン起動（Service Worker）。一度開いておけば圏外でも画面が開く
- 設定（右上の歯車）でバージョン確認（表示中の版とサーバー上の版を比較）
- 削除の取り消し（直前の1件のみ、トーストから「元に戻す」）
- 一覧でのタイトル・メモ検索（絞り込みの列の虫めがねで開く）

### Discord の通知

| 通知 | 時刻 (JST) | 内容 |
|---|---|---|
| 朝 | 毎日 6:47 | 長く残っているもの・期限切れ・今日が締切・7日以内・定期予定。期限切れと今日が締切の行に「✅完了」リンク |
| 夜の再通知 | 月〜土 20:23 | 期限切れと今日が締切だけ（繰り返しは、次の回が今日で、まだ終わっていないもの）。無ければ何も送らない |
| 週次レビュー | 日曜 20:23 | 来週7日間の見通し・1週間の達成（2通に分けて送る。2通目は繰り返しの調子・負荷予報・月初めの支出まとめ） |

- 負荷予報は来週・再来週の件数とカテゴリ別の内訳。1週間の合計が6件以上、または1カテゴリが3件以上で ⚠️ を付ける
- 支出まとめは月の最初の日曜だけ。「サブスクなど」のメモにある `¥1,980`・`1980円` を月額に換算して合計する
- 見出しの件数と負荷予報には、自動完了の予定（締切を過ぎると自動で完了になるもの）を数えない。一覧には出す（件数は「N件＋自動完了M件」）
- 旧環境にあった「毎週月曜の `data.json` の添付」は、Cloudflare 版では送らない（D1 に世代バックアップがあり、メモを含む全データを Discord に置かないため）

## セットアップ

### 1. Worker をつくる

1. Cloudflare の Workers & Pages で、このリポジトリ（`main`）を GitHub 連携（Workers Builds）して Worker `deadline-tracker` をつくる。ビルドとデプロイの設定は `wrangler.jsonc` が持っている
2. D1 のデータベースを作り、`wrangler.jsonc` の `d1_databases` の `database_id` を自分のものにする（別のアカウントで使うとき。プレビュー用は別のデータベース）。表は最初のリクエストで自動で作られる
3. シークレット `APP_KEY` を登録する（次の「Cloudflare の設定」）
4. `https://<Worker名>.<サブドメイン>.workers.dev/` を開く。動作確認は `GET /api/health`（認証なし）

iPhone では Safari で開いて共有ボタン →「ホーム画面に追加」でアプリのように使える。ここまでで、締切の管理と `.ics` の書き出しは使える。以降は任意の機能。

### 2. 端末をつなぐ

1. アプリの **設定（右上の歯車）→ 端末間の同期** に、アクセスキー（`APP_KEY` の値）を入れる。「この端末にアクセスキーを保存」にすると、暗号化してその端末に残る（共用の端末では保存しない）
2. 何も入っていない端末では、キーを入れた時点で保存先の内容を自動で読み込む。アクセスキーを保存した端末では、この端末に未同期の変更が無いときに限り、起動時・画面復帰時・10分ごとに他の端末の更新を自動で取り込む。設定の「Cloudflareへ自動で同期する」をオンにすると、登録・編集・完了などのあと数秒で自動で送信する（初めはオフ）
3. 手動の「同期」「読み込み」もできる。他の端末の新しい更新があるのに同期しようとすると確認を挟み、同意すると**上書き前の内容を世代バックアップに残してから**上書きする（自動同期は、この場合は上書きせずに止まる）

> 古い・違うアクセスキーの端末は、`401` を受けた時点で自動の通信を止め、「アクセスキーが違うため…」と一度だけ知らせる（同じ回線の正しい端末を、Worker の失敗回数の制限で巻き込まないため）。設定でキーを入れ直すと再開する。

### 3. Discord と Gmail をつなぐ（任意）

登録するまで、何も送らない（旧環境と二重に届くこともない）。

- Discord: チャンネル設定 →「連携サービス」→「ウェブフック」で URL を取得し、シークレット `DISCORD_WEBHOOK_URL`（と、あれば `DISCORD_USER_ID`・`APP_URL`）に登録する
- Gmail: Google Cloud で OAuth クライアントを作り、`gmail.send` だけのリフレッシュトークンを取得して、シークレット `GOOGLE_*`・`MAIL_TO` に登録する（OAuth 同意画面は「本番」にする。「テスト」のままだと7日で切れる）。詳しくは `docs/cloudflare-migration.md`
- 動作確認は、設定の「Discordへ今すぐ送信」か、次の API の `GET`（送らない）→ `POST`（送る）

### 4. アプリの設定

設定（右上の歯車）で、当日リマインドの時刻、カテゴリ、テーマ（自動・ライト・ダーク）、演出・効果音などを変更できる。この設定は端末ごとで、同期しない。

## Cloudflare の設定

秘密はすべて **Cloudflare のシークレット**（Worker の設定 → 変数とシークレット）に、種類を**「シークレット」**で登録する。「変数」（テキスト）で登録すると、次のデプロイで消えることがある。**値は、このリポジトリにもログにも書かない。**

| 名前 | 用途 | 必須 | 未設定のとき |
|---|---|---|---|
| `APP_KEY` | アクセスキー。API とアプリの認証。24文字以上のランダムな値 | 必須 | API が使えない（503） |
| `FEED_TOKEN` | 購読用 `.ics` の URL に入れるトークン。24文字以上のランダムな値で、`APP_KEY` とは別にする | 任意 | `/ics/…` は 404 |
| `DISCORD_WEBHOOK_URL` | Discord の Webhook の URL | 任意 | 朝・夜の再通知・週次レビューを送らない |
| `DISCORD_USER_ID` | 通知の先頭でメンションするユーザーの ID | 任意 | 誰にもメンションしない |
| `APP_URL` | 通知のリンク（「アプリを開く」・「✅完了」）に使うアプリの URL。例: `https://<Worker名>.<サブドメイン>.workers.dev/` | 任意 | リンクを出さない |
| `DONE_LINKS` | `0` にすると「✅完了」リンクを付けない | 任意 | 付ける |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REFRESH_TOKEN` | Gmail API（`gmail.send` のみ）での送信 | 任意 | メールを送らない |
| `MAIL_TO` | メールの送り先（自分） | 任意 | メールを送らない |
| `MAIL_FROM` | メールの送信元 | 任意 | `MAIL_TO` と同じ |

## API

`/api/health` 以外は、すべて `Authorization: Bearer <アクセスキー>` が必要。認証の失敗が続くと、IP ごとに10分止める（正しいキーで認証できると、その IP の失敗の記録は消える）。

| 呼び方 | 内容 |
|---|---|
| `GET /api/health` | 動作確認（認証なし） |
| `GET /api/data` | 締切データと版（`rev`） |
| `PUT /api/data` | 締切データの保存。`If-Match: <rev>` が今の版と違えば `409`。`?force=1` で上書き、`?backup=1` で上書き前を必ず世代バックアップに残す |
| `GET /api/snapshots` | 世代バックアップの一覧（新しい順に最大200件） |
| `GET /api/snapshots/<id>` | 世代バックアップ1件の中身 |
| `GET /api/feed` | 未完了の締切の一覧。`?days=14` |
| `GET /api/ics` | `.ics`（メモあり。`?memo=0` でメモなし。`?dayHour=9` は当日リマインドの時刻で、アプリが端末の設定を渡す） |
| `GET /ics/<FEED_TOKEN>.ics` | 購読用の `.ics`（メモなし。カレンダー名「締切トラッカー」と、1時間ごとの更新を指定する）。認証は URL の中のトークン。URL は `https://<Worker>/ics/<FEED_TOKEN>.ics` で、カレンダーアプリで「照会カレンダー」として追加する |
| `GET /api/feed-url` | 購読用 URL を返す（`FEED_TOKEN` から組み立てる。認証つき。未設定なら `ok:false`）。アプリの設定「カレンダーで購読する」が使う |
| `GET /api/mail` | 締切のメールの件名と本文を作る（送らない）。`?target=today` `tomorrow` `auto` |
| `POST /api/mail` | 締切のメールを今すぐ自分宛てに送る |
| `GET /api/digest` | Discord に送る文面を作る（送らない）。`?kind=morning`（既定）`evening` `weekly` |
| `POST /api/digest` | 今すぐ Discord に送る。`?kind=` は同じ |

購読用 `.ics` の URL を知っている人は、タイトル・日時・カテゴリを読める（メモは入らない）。外に出したくなければ `FEED_TOKEN` を登録しない。

## 定時の処理

Cron は UTC で書く（`UTC = JST − 9時間`）。無料プランの本数の上限のため、1本で複数の仕事をする。1つの仕事が失敗しても、同じ Cron の残りは実行し、最後にまとめて失敗として投げる（Cloudflare の Cron の履歴に残る）。

| Cron（UTC） | 時刻（JST） | する仕事 |
|---|---|---|
| `47 21 * * *` | 毎日 6:47 | 朝の締切一覧を Discord へ |
| `23 11 * * *` | 毎日 20:23 | 翌日分の締切のメールを自分宛てに ＋ 月〜土は夜の再通知、日曜は週次レビューを Discord へ |
| `23 20 * * *` | 毎日 5:23 | 当日分の締切のメールを自分宛てに ＋ 世代バックアップの間引きと掃除 |

メールの件名は「【締切トラッカー】M/D（曜）の締切」で固定（Claude のルーティンがこの件名で Gmail を検索して読む）。Cloudflare の Cron は数分遅れることがある。

## バックアップと復元

データは D1 にある。端末の localStorage は写しで、Cloudflare に同期できる。

| 手段 | 作られるタイミング | 備考 |
|---|---|---|
| 世代バックアップ（D1） | 保存のとき、前回のバックアップから30分以上空いていれば、上書き前の内容を保存。`?force=1`・`?backup=1`・上書きの確認に同意した同期では必ず残す | 毎日 5:23 に間引く: 直近14日は全部、〜90日は週に1つ、それ以前は月に1つ |
| 手動の JSON 書き出し | 設定（右上の歯車）の「JSONで書き出す」 | 任意の時点で |

### 世代バックアップから戻す

**アプリから**（設定（右上の歯車）→ バックアップと復元 →「世代バックアップ（Cloudflare）」）

1. 下の「端末間の同期」にアクセスキーを入れ、「世代バックアップの一覧を読み込む」を押す（一覧は、押したときだけ読む。キーを保存していれば入れ直しは要らない）
2. 日時・版・大きさが新しい順に並ぶ。戻したい時点の「中身」を押すと、締切の件数と先頭の5件が出る
3. 「この時点に戻す」→ 確認 → 戻る。**先に今の Cloudflare の内容が新しい世代バックアップに残る**ので、戻しすぎても、もう一度戻せる。使った世代バックアップは消えない
4. この端末にまだ同期していない変更があると、確認にその旨が出る（戻すと失われる）。残したいときは、先に「JSONで書き出す」か同期する
5. ほかの端末は、次の自動の取り込み（または手動の「読み込む」）で、戻した内容になる

**API から**（アプリが使えないとき）

1. 一覧を見る。`id`・`at`（保存した時刻。epoch 秒）・`rev`・`size` が新しい順に返る

   ```
   curl -H "Authorization: Bearer $APP_KEY" https://<Worker>/api/snapshots
   ```

2. 戻したい時点の `id` の中身を取る。返ってくる JSON の `data` が、その時点の締切データ

   ```
   curl -H "Authorization: Bearer $APP_KEY" https://<Worker>/api/snapshots/<id>
   ```

3. `data` の部分だけをファイル（例: `restore.json`）に保存し、アプリの設定（右上の歯車）で「JSONを読み込む」。端末のデータが置き換わる
4. 「同期」を押す。他の端末の新しい更新があると確認が出るので、「バックアップ付きで上書き」を選ぶ（今の内容も世代バックアップに残る）

アクセスキーをシェルの履歴に残したくないときは、環境変数 `APP_KEY` に入れて使い、使い終わったら消す。

### アクセスキーを変える

1. Cloudflare の Worker の設定 → 変数とシークレット で、`APP_KEY` を新しい値（24文字以上のランダムな値。種類は「シークレット」）で保存してデプロイする
2. 使っている端末ごとに、アプリの設定でアクセスキーを入れ直す（「この端末にアクセスキーを保存」）。入れ直すまで、その端末の自動同期は止まる（`401` で止まり、一度だけ知らせる）
3. キーをなくしたときも同じ手順でよい。データは D1 にあるので、キーを変えても失われない
4. 購読用 `.ics` の URL を変えたいときは、`FEED_TOKEN` を新しい値にして、カレンダーの購読を入れ直す

### セットアップ（旧）

#### 1. アプリを公開する

1. `index.html`・`app.js`・`styles.css`・`manifest.webmanifest`・`service-worker.js`・`assets/` フォルダを、自分の Public リポジトリにアップロードする
2. **Settings → Pages** を開き、Source を `Deploy from a branch`、Branch を `main / (root)` にして Save
3. 1〜2分待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で開く

iPhone では Safari で開いて共有ボタン →「ホーム画面に追加」でアプリのように使える。

ここまでで、締切の管理と `.ics` の書き出しは使える。以降は任意の機能。

#### 2. 端末間で同期する

1. Private リポジトリ（例：`deadline-data`）を新規作成する
2. **Settings（アカウント） → Developer settings → Fine-grained tokens** でトークンを発行する
   - Repository access: 作成した Private リポジトリのみ
   - Permissions: **Contents → Read and write**
3. アプリの **設定（右上の歯車） → 端末間の同期とDiscord通知** に、ユーザー名・リポジトリ名・トークンを入力する
4. **GitHubに同期する** で送信、別の端末では **GitHubから読み込む** で受信

> 読み込むと、その端末のデータは GitHub 上の内容で**置き換わる**（実行前に確認が出る）。両方の端末で別々に編集してから読み込むと片方が消えるため、「登録するのは主に1台、他は読み込むだけ」という使い方が安全。

#### 3. Discord へ毎朝の連絡を送る

1. Discord のチャンネル設定 →「連携サービス」→「ウェブフック」で URL を取得する
2. Private リポジトリに `.github/workflows/daily-digest.yml` と `.github/scripts/`（`send_digest.sh`・`build_ics.py`）を配置する
   - `send_digest.sh` は **`deadline-data-template/` のもの**（設定値は空にしてある）、それ以外は元の deadline-data（このアプリのデータ用リポジトリ）の同じ場所のファイルを写す
   - GitHub 上で **Add file → Create new file** を選び、ファイル名にスラッシュを含めて入力するとフォルダごと作られる
   - ワークフロー内の `run:` のパスと、スクリプトの実際の置き場所を一致させること
3. Webhook URL を設定する（Private リポジトリの Secrets に `DISCORD_WEBHOOK_URL` として登録するか、`send_digest.sh` の冒頭に記入する）。メンション先などもスクリプト冒頭で設定する
4. Private リポジトリの **Actions** タブ → **Run workflow** で動作を確認する（**dry_run** にチェックすると送らずにログで本文を確認できる）

> ⚠️ Webhook URL をスクリプトに直接書く場合、**このファイルは必ず Private リポジトリに置くこと**。万一漏れた場合は Discord 側でウェブフックを削除すれば即座に無効化できる。Secrets に登録した値はワークフローから渡され、スクリプト内の値より優先される。

#### 4. 任意の追加機能

どれも元の deadline-data（このアプリのデータ用リポジトリ）の対応するファイルを自分の Private リポジトリに置くだけで、置かなければ何も起きない。

| 機能 | 置くもの | 必要な設定 |
|---|---|---|
| モーニングブリーフ用の一覧 | `build-feed.yml`・`build_feed.py` | なし（`GITHUB_TOKEN` でコミットする） |
| 締切を Gmail で自分宛てに送る | `send-feed-mail.yml`・`send_feed_mail.py` | Secret に `GMAIL_ADDRESS`・`GMAIL_APP_PASSWORD`（アプリパスワード）。未登録なら送らない。メール本文の先頭に「おすすめの順番」が付く |
| 購読用 .ics（URL で購読） | `publish-ics.yml` | 秘密 Gist を作り、Secret に `GIST_ID`・`GIST_TOKEN`（Gists: Read and write）。未登録なら何もしない |
| バックアップの間引き | `prune-backups.yml`・`prune_backups.py` | なし（毎月28日。直近14日は全部、〜90日は週1つ、それ以前は月1つ残す） |
| data.json の中身チェック | `validate_data.py`・`check.yml` | なし（id の重複・日時・繰り返しの値などを見て、エラーなら失敗） |

> ⚠️ 購読用 .ics の秘密 Gist は、**URL を知っていれば誰でも読める**。メモは書き出さないが、タイトル・日時・カテゴリは外に出る。
> 外に出したくなければ Secret を登録しない（登録しない間は何も公開されない）。

#### `.github/workflows/daily-digest.yml`

```yaml
- cron: "47 21 * * *"     # UTC 21:47 = JST 6:47（朝）
- cron: "45 12 * * 0"     # UTC 12:45 日曜 = JST 21:45 日曜（週次レビュー）
- cron: "47 11 * * 1-6"   # UTC 11:47 月〜土 = JST 20:47 月〜土（夜の再通知）
```

cron は UTC 基準（`UTC = JST − 9時間`）。GitHub の cron は混雑時に遅れるため、「0分ちょうど」を避けると比較的安定する。数十分の遅延は仕様上ありうるので、「朝のうちに届けばよい」程度の想定で使う。

### データとバックアップ（旧）

保存先はブラウザの localStorage で、端末ごとに独立している。復元手段は3つある。

| 手段 | 作られるタイミング | 復元方法 |
|---|---|---|
| GitHub のコミット履歴 | 同期のたび | `data.json` → History から任意の時点を取得 |
| `backups/` の自動バックアップ | 上書きの確認に同意して同期したとき | `backups/data-日時.json` を取得して「JSONを読み込む」。月1回、古いものから間引かれる |
| Discord への週次添付 | 毎週月曜の朝 | 添付を保存 → 設定（右上の歯車）の「JSONを読み込む」 |
| 手動の JSON 書き出し | 任意 | 同上 |

最も細かく戻せるのはコミット履歴。`backups/` は間引かれるので、古い時点に戻したいときもコミット履歴を使う。

## URLパラメータ

`?export=` を付けて開くと、`.ics` の書き出しが自動で始まる。

| 値 | 対象 |
|---|---|
| `all` | 未完了の全件 |
| `once` | 締切のみ（繰り返しを除く） |
| `rep` | 定期予定のみ |

Discord の毎朝の通知には `?export=all` のリンクが載る。

`?done=<締切のID>` を付けて開くと、その締切の確認（「○○を完了にしますか？」）が出て、承認すると完了にする。
通知の「✅完了」リンクの行き先で、確認なしでは完了にしない。保存先（Cloudflare）の新しい内容が無いか確かめてから（最大4秒）探し、
見つからない・すでに完了のときはその旨を知らせる。繰り返しの締切は今回の分を完了にして次回へ進む。
アドレスのパラメータは処理の直後に消すので、再読み込みで二重に完了にはならない。

## 既知の注意点

**iPhone でカレンダーに取り込むとき**

Discord などの添付ファイルを直接タップすると、iOS は「照会カレンダー」として登録してしまい、更新がすぐ反映されない。通知内の「カレンダーに入れる」リンクから開くか、添付を長押し →「ファイルに保存」してから開くこと。

**繰り返し予定の編集**

カレンダー画面に並ぶ繰り返しの回は表示用の複製のため、完了・編集は「定期予定」の一覧から行う。カレンダーからは「この回は休み」のみ操作できる。

**同期は上書き**

差分のマージは行わない。他の端末の新しい更新があるときは、読み込むか、バックアップ付きで上書きするかを選ぶ（「セットアップ」の「2. 端末をつなぐ」）。

**アクセスキー（旧環境では GitHub トークン）・Discord Webhook URL の保存と CSP**

設定（右上の歯車）で「この端末にアクセスキーを保存」（旧環境では「この端末にトークンを保存」）「この端末に保存（Webhook URL）」を選ぶと、アクセスキー・トークンと Webhook URL は**暗号化して**保存する（同じ仕組み・同じ鍵を使う）。ブラウザが端末ごとに作る「取り出せない鍵」（WebCrypto）で AES-GCM 暗号化し、鍵は IndexedDB、暗号文（`enc1:...`）は localStorage に置く。以前の版が平文で保存していた値は、開いたときに自動で暗号化し直す。

- 守れるのは、localStorage の中身だけが漏れた場合（バックアップの流出・保存領域の抜き出し・画面の写り込みなど）。同じページで動くスクリプトが乗っ取られた場合は、鍵を使って復号されてしまう。そちらは CSP（`script-src 'self'`：`app.js` 以外のスクリプトを実行しない、通信先は自分と同じオリジン〔Worker の `/api/`〕・GitHub・Discord だけ）で防ぐ
- ブラウザのサイトデータを消すなどで鍵が失われると、保存済みの値は読めなくなる。そのときは自動で消えるので、入力し直す（Webhook URL は空欄のまま送れば、GitHub の設定から取り直せる）
- 暗号化できない環境（IndexedDB / WebCrypto が使えない）では、平文で残さず保存しない。設定（右上の歯車）にその旨が出て、今回の操作にだけトークンを使う
- Worker から配信するときの CSP と、`frame-ancestors 'none'` などのセキュリティヘッダーは、`scripts/build.mjs` が `index.html` の meta から `web/_headers` に作る。
- CSP のため、HTML にインライン `<script>` や `onclick="..."` を書かない（イベントは `app.js` で付ける）。CSS は `styles.css` に置き、`<style>` 要素も `style="..."` の属性も許さない（`style-src-elem`・`style-src-attr 'none'`。`'unsafe-inline'` は付けない）。固定の見た目は `styles.css` のクラスに置き、計算で決まる値（色・幅・位置）は `data-st="プロパティ:値;…"` で渡す（`app.js` の `applyDyn` が、要素ができてから CSSOM で付ける）
