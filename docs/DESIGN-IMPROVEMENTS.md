## 確かめた方法

- テスト用の架空データ（`test/fixtures/data.json`）を、日付を今日の前後にずらしてブラウザ（Chromium）で表示した
- スマホ幅（390×844）のライト・ダークと、パソコン幅（1280×900）を見た。スクリーンショットは `docs/design-screenshots/` にある
- Web フォント（IBM Plex Sans JP）は読み込まずに撮った（環境の都合）。字形は実機と違うが、配置・大きさの判断には影響しない
- 日付入力が「10/29/2026」と出ているのは撮影したブラウザが英語設定のため。日本語の iPhone では日本の形式になる
- 実機（iPhone の Safari・ホーム画面のアプリ）では確かめていない。各項目の「完了の条件」で実機の確認を求めている

## 今のデザインの方針（守るもの）

`styles.css` の冒頭に書かれている方針は、改善案でも守る。

- 紙の手帳・台帳を下敷きにする。角はボタン・カードが 6px、ダイアログ・パネルが 10px（D21）。影は抹茶・石だけごく薄く付け（墨は影なし）、グラデーション・ぼかしは使わない
- 階層は罫線と文字の大きさ・書体で作る
- 状態色（赤・琥珀・青・緑）は状態にだけ使い、必ず記号と文字の「判子」と組にする（色覚の違いへの配慮）

この方針は一貫していて、よくできている。以下は方針の範囲で、読みやすさ・押しやすさ・迷いにくさを上げる案。

**D21 で変える点（2026-11-09 に持ち主が了承）**：角は 2px から 6px（ボタン・カード）に、影は抹茶・石のテーマだけごく薄く付ける（墨は影なし）。紙の手帳の世界観（罫線・判子・演出の「手帳風」）は残す。D21 を入れたら、上の1行目を書き直す。

## D1. ヘッダーの「7日以内 0」と、一覧の「今週（7日以内）」の件数が食い違って見える

- 重大度：中
- 分類：使いやすさ
- 状態：完了（ラベルを「締切 7日以内」にし、定期予定があれば「＋定期 N」を添えた。数え方は変えていない。`headerCount` に切り出して単体テストを追加）

**問題の内容と該当箇所**

ヘッダー右上の大きな数字は「繰り返しでない締切」だけを数える（`app.js:571-586`。定期予定は常にあるため除く、という意図のコメントがある）。
一方、一覧の「今週（7日以内）」の見出しの下には、定期予定（繰り返し）のカードも並ぶ。
スクリーンショット `docs/design-screenshots/phone-list.png` では、ヘッダーが「0 / 7日以内」なのに、そのすぐ下に「今週（7日以内）」のカードが2枚ある。

**なぜ問題なのか**

画面でいちばん大きな数字が、すぐ下の内容と合わないので「数え間違い？」と迷う。数字が主役の画面なので、信頼を損ねやすい。

**改善案**

- ヘッダーのラベルを、何を数えているかが分かる言葉にする（例：「締切 7日以内」）。定期予定があれば、その下に小さく「＋定期 2」と添える
- または一覧の見出しを「今週の締切」「今週の定期予定」に分ける
- 数え方そのもの（定期・自動完了を除く）は変えない（最近の変更 `2ffeaee`・`71ed1ed` の意図を守る）

**実装担当への指示文**

> 目的：ヘッダーの件数と一覧の見出しが食い違って見えないよう、ラベルで「何を数えているか」を示す。数え方は変えない。
> 対象ファイル：`app.js`（`render` の 568〜586 行付近、ヘッダーの `cntNum`・`cntLabel`）、`index.html`（45 行の `.count`）、`styles.css`（`.count`）。
> やること：
> 1. 期限切れが無いとき、`cntLabel` を「締切 7日以内」にする。7日以内の定期予定（`isRepeating`）の件数が1以上なら、ラベルの下に小さく「＋定期 N」を出す（新しい要素を `index.html` の `.count` の中に足す）。0件なら出さない
> 2. 期限切れ・超過・定期予定の画面の表示は今のまま
> 3. 文字の大きさは `styles.css` の既存の `.count` の小さい文字にそろえる。色は `--ink-3`（状態色は使わない）
> 4. `index.html` の `app.js?v=...`・`styles.css?v=...`・`build-stamp` を更新する（`index.html` 18〜19 行のコメントの決まり）
> 完了の条件：`npm test` と `npm run build` が成功する。テスト用データ（`test/fixtures/data.json`）を読み込んだ画面で、ヘッダーのラベルと一覧の見出しが矛盾しない。スマホ幅 390px でヘッダーが2行に崩れない。コミットメッセージは `fix: 要約`。

## D2. カードの操作ボタンが小さく、押し間違えやすい

- 重大度：中
- 分類：使いやすさ
- 状態：完了（タッチ端末で「完了にする」「…」と、開いた中のボタンを高さ 44px 以上に。「削除」は16px離す。マウスの見た目は変えていない）

**問題の内容と該当箇所**

カードの操作ボタン `.act` は上下 3px の余白と 12.5px の文字で、高さはおよそ 24px（`styles.css:156-161`）。
「…」（ほかの操作）も同じ大きさで、カードの右端に離れて置かれている（`app.js:911` 付近の `.more-btn`）。
`docs/design-screenshots/phone-list.png` の「完了にする」と「…」を参照。

WCAG 2.2 の AA（2.5.8）は 24×24 CSS px が最低限で、ぎりぎり。
Apple は 44pt、Material は 48dp を目安にしていて、毎日押す主要な操作としては小さい。

**なぜ問題なのか**

「完了にする」はこのアプリでいちばん押す操作。小さいと押し損じや、隣の操作の誤タップにつながる。
「…」の中には「削除」もある。

**改善案**

- タッチ操作の端末（`@media (pointer:coarse)`）では、`.act` の高さを 44px 以上にする。見た目の大きさは変えず、余白（押せる範囲）だけを広げる方法でもよい
- 「…」は「完了にする」と同じ行の右端に置いたまま、押せる範囲を 44×44px にする
- 「…」を開いた中の「削除」は、他の操作と間を空けて最後に置く（今も最後。間隔を広げる）
- パソコン（マウス）では今の詰まった見た目のままでよい

**実装担当への指示文**

> 目的：スマホで、カードの「完了にする」「…」などの操作を押しやすくする。
> 対象ファイル：`styles.css`（`.act`・`.act.main`・`.more-btn`・`.more` の 156〜162 行付近）、必要なら `app.js`（`cardOf` 843〜915 行付近。構造を変える場合だけ）。
> やること：
> 1. `@media (pointer:coarse)` の中で、`.act` を `min-height:44px`、左右の余白を広げ、`display:inline-flex; align-items:center` にする。`.more-btn` は `min-width:44px; min-height:44px`
> 2. 「…」を開いたときの操作の並び（`.more`）は、各ボタンの間を 8px 以上空け、「削除」（`.act.danger`）の前は 16px 以上空ける
> 3. デザインの方針（`styles.css` 冒頭：角 2px、影なし、罫線で区切る）は守る
> 4. マウスの環境（`pointer:fine`）の見た目は変えない
> 5. `index.html` の `styles.css?v=...`・`build-stamp` を更新する
> 完了の条件：`npm test` と `npm run build` が成功する。ブラウザの開発ツールでスマホ表示（390px、タッチ）にし、「完了にする」と「…」の押せる範囲が 44×44px 以上ある（要素の大きさで確認）。可能なら iPhone の実機で、誤タップしないことを確かめる。コミットメッセージは `fix: 要約`。

## D3. 画面の下に、タブ・登録ボタン・トーストが重なる

- 重大度：中
- 分類：使いやすさ
- 状態：完了（スマホでは登録ボタンを右下の小さめの四角に寄せ、トーストを本文と同じ左右の余白でその真上に出す）

**問題の内容と該当箇所**

スマホでは、画面の下に次の3つが縦に積み重なる。

- 固定のタブ
- 中央の「＋ 締切を登録」（`.fab`、`styles.css:284` と 505 行）
- トースト（`.toast`、337 行と 506 行）

`docs/design-screenshots/phone-list.png` では、トーストと登録ボタンが一覧のカード（「これから」の1枚目のタイトル）を隠している。
カレンダー（`phone-cal.png`）や今週（`phone-week.png`）でも、末尾の説明文に登録ボタンが重なる。

Material Design は、通知（スナックバー）を浮いたボタンの上に出し、ナビゲーションなど大事な操作の前に重ねないよう勧めている（参考の表）。今の並び（トーストがボタンの上）はこの点で合っている。
ただし、横幅いっぱいの大きなボタンが中央にあるため、内容を隠す面積が大きい。

**なぜ問題なのか**

画面の下の 1/4 近くが常に覆われ、スクロールしないと読めない内容が増える。
トーストの「元に戻す」と登録ボタンが近く、押し間違えやすい。

**改善案**

- 登録ボタンを右下の小さめの四角いボタン（「＋」と「登録」、44px 以上）にして、中央の内容を空ける。手帳風の方針に合わせて、影ではなく罫線で浮きを表す
- 一覧以外の画面（今週・カレンダー・完了・設定）では、下にスクロールしている間は登録ボタンを隠すか、タブバーの中に「＋」を置く案もある（どちらか1つを選ぶ）
- トーストは登録ボタンと重ならない高さを保ったまま、横幅を本文の幅に合わせる

**実装担当への指示文**

> 目的：スマホで、画面下の登録ボタンとトーストが一覧の内容を隠さないようにする。
> 対象ファイル：`styles.css`（`.fab` 284〜291 行、`.toast` 337〜342 行、スマホ用の 500〜510 行付近の `@media`）、必要なら `app.js`（`#fabAdd` の扱い、3982 行付近）。
> やること：
> 1. スマホ幅では `.fab` を右下（`right:16px`）に寄せ、幅を内容に合わせる（「＋ 登録」程度）。高さは 48px 以上。影は使わず、`border:1px solid var(--ink)` と背景色で目立たせる（`styles.css` 冒頭の方針）
> 2. `.toast` は `.fab` の上に出したまま、左右の余白を本文と同じにして、`.fab` と縦に 8px 以上離す
> 3. 本文の下の余白（`body` の `padding-bottom`、49 行と 504 行）を、登録ボタンの高さ＋トーストの分に合わせて見直し、最後のカードや説明文が隠れないようにする
> 4. パソコン幅（960px 以上）の配置は変えない
> 5. `index.html` の `styles.css?v=...`・`build-stamp` を更新する
> 完了の条件：`npm test` と `npm run build` が成功する。390×844 の表示で、一覧・今週・カレンダーを一番下までスクロールしたとき、最後の要素が登録ボタンに隠れない。トーストが出ている間も「元に戻す」ボタンと登録ボタンが重ならない。コミットメッセージは `fix: 要約`。

## D4. 登録画面で、締切日より前にチェックボックスが3つ並ぶ

- 重大度：中
- 分類：使いやすさ
- 状態：完了（並びを「タイトル → 締切日・時刻 → 終日 → カテゴリ・繰り返し → 回数 → メモ → 詳しい設定」にし、期間・自動完了・色・帯の表示は折りたたんだ。設定済みの予定では開いて出る）

**問題の内容と該当箇所**

登録画面（`index.html:66-116`）は、次の順に並ぶ。

1. タイトル
2. 「何日かにまたがる」「終日」「期限を過ぎたら自動的に完了」の3つのチェックボックス
3. 締切日・時刻
4. カテゴリ・繰り返し

**問題の内容と該当箇所**

- 二重に鳴る：完了・登録など専用の音がある操作で、全ボタン共通の音（`app.js` 3771 行付近の click の処理）も同時に鳴る。完了の音が濁る
- 割れやすい：音の種類ごとに出力（`ctx.destination`）へ直接つないでいる。続けて押すと重なって割れることがある
- 毎回同じ音：雑音のバッファを毎回 `createBuffer` で作り、高さ・長さも毎回同じ。何度も聞くと作り物らしさが目立ち、連打すると古い端末で負荷がかかる

**なぜ問題なのか**

どの音を作っても、この3つが残っていると、うるさく・単調に聞こえる。円卓議論で5人全員が10点を付けた、すべての音の土台。

**改善案**

1. 専用の音がある操作では、全ボタン共通の音を鳴らさない（1操作1音）
2. すべての音を、マスター（音量 0.6）→ コンプレッサー（`DynamicsCompressor`、threshold −18dB）→ 出力、の順に通す
3. 雑音のバッファは、起動時（最初に音を鳴らすとき）に1秒ぶんを1回だけ作る。毎回、読み出す位置を乱数で変えて使う
4. 1秒以内に続けて鳴ったら、2回目以降の音量を 0.5 倍にする
5. 音ごとに、高さ・長さ・音量を少しずつ乱数でばらつかせられるようにする（目安：高さ ±5〜15%、音量 ±15〜30%）
6. 音の立ち上がりと消え際に、必ず 2〜5ms の傾きを付ける（「プツッ」を防ぐ）
7. 印のアニメーションと一緒に鳴る音は、印が紙に着く時刻に合わせて鳴らせるようにする（遅らせる時間を引数で渡す）

**実装担当への指示文**

> 目的：効果音の鳴らし方の土台を作り直し、1回の操作で音が1つだけ鳴り、続けて鳴らしても割れず、毎回少しずつ違って聞こえるようにする。音色そのものは変えない（音色は D16・D17）。
> 対象ファイル：`app.js`（`SFX` 3714 行付近、`playSfx` 3720 行付近、`stampTap` 3749 行付近、ボタンの click の処理 3771 行付近、`pageTurn` 3780 行付近、`audioCtx` 3697 行付近、音を鳴らしている場所：`deleteItem` 1361 行・登録 3511 行・`complete` 3635 行・画面の切り替え 3687 行）、テスト `test/unit/app-logic.test.js`。
> やること：
> 1. 専用の音がある操作のボタン（完了にする・登録の保存・削除の確認など）には `data-sfx="own"` を付け、click の処理はその要素（と子要素）では共通の音を鳴らさない。どのボタンが対象かは、`playSfx` を呼んでいる操作から洗い出す
> 2. `audioCtx()` で、マスターの GainNode（0.6）と DynamicsCompressor（threshold −18、knee 12、ratio 4、attack 0.003、release 0.15）を一度だけ作り、すべての音をここへつなぐ
> 3. 雑音のバッファ（1秒・モノラル）を一度だけ作る関数 `noiseBuffer(ctx)` を作り、`stampTap`・`pageTurn` などは `AudioBufferSourceNode.start(when, offset, duration)` の offset を乱数にして使う
> 4. 最後に鳴った時刻を覚え、1秒以内なら音量を 0.5 倍にする（純粋な関数 `sfxGain(lastAt, now)` に切り出してテストする）
> 5. 乱数のばらつきを返す小さな関数 `jitter(value, ratio)` を作ってテストする（テストでは乱数を差し替えられるようにする）
> 6. `playSfx(kind, opts)` に `opts.delay`（秒）を足し、鳴らす時刻を遅らせられるようにする
> 7. 設定で音が「なし」のとき、AudioContext を作らない・何も鳴らさない今の動きは変えない
> 制約：ES5 風の書き方。依存を足さない。音声ファイルを使わない。
> 完了の条件：`npm test` と `npm run build` が成功する。iPhone の実機で、完了を押したときに音が1つだけ鳴る（確かめられたら状態に追記する）。1秒に5回ボタンを押しても音が割れない。コミットメッセージは `fix: 要約`。

**改善案**

  - 補助の胴：正弦波 300→200Hz を 60ms で下げる。音量 0.05
  - 刻印：雑音をバンドパス 2.5kHz（Q 1）に通した 6ms の粒を1つ。音量 0.05

- **皆済「とんとん…どん」**

## D19. 音と同時に画面の「済」の印を押す。動きを減らす設定でも印を出す

1. 手帳風で、動きを減らす設定のとき：印を動きなし（拡大や回転なし、色と形だけ）で 0.4 秒見せてから、カードを畳まずに一覧を描き直す
2. 音は、印が表示される時刻に合わせて鳴らす（D15 の `opts.delay`）。印より先に音が鳴らないようにする
3. （任意。決勝 4.00 点）完了を押した瞬間、カードのタイトルに朱色の取り消し線を引く（0.15 秒、CSS だけ）。印と組で「済んだ」がひと目で分かる

**実装担当への指示文**

> 対象ファイル：`app.js`（`complete` 3620 行付近、`stampCard` 3663 行付近、`motionOn` 3655 行付近）、`styles.css`（`.done-stamp` 624 行付近、`prefers-reduced-motion` の指定 648 行付近）、テスト `test/unit/app-logic.test.js`。

> 制約：ES5 風の書き方。依存を足さない。影・グラデーションを使わない（デザインの方針）。

- iPhone のスピーカーで、雑音中心の音が「ザッ」としか聞こえず区別できない → 正弦波の胴を強める。手帳風の音をやめて、柔らかいベルの音で統一することも検討

# 第5回で追加した項目（2026-11-09）：テーマの仕組み（Astryx の考え方を借りる）

持ち主の希望「Meta のデザインシステム Astryx（https://github.com/meta/astryx）の考え方を参考に、画面のデザインを改善したい。Astryx 自体（React のコンポーネント）は入れない」を受けたもの。
持ち主の指定で、今回はテーマの計画表だけを記載する（今日のウィジェット・表のページ・詳細のレイアウトは、ここには書かない）。

**Astryx から読んだこと**（リポジトリの README、`docs/architecture/theme-tokens.md`、`packages/themes/matcha`・`stone` の定義と公開パレット）

- テーマは「CSS 変数の上書きの集まり」。部品は意味で名付けた変数（例：`--color-text-primary`、`--color-background-surface`）だけを参照し、テーマは値だけを変える。生の色のパレットを部品から直接使わない
- 変数の名前は「種類-役割-段階」。余白は `--spacing-N`（N × 0.25rem）、角は `--radius-inner`／`element`／`container`／`full`、影は `--shadow-low`／`med`
- 部品の名前と使い方のルールをそろえ、初めて見る部品でも動きが予想できるようにする（Principles の「Strong, documented conventions」）

## D21. テーマの仕組み：見た目の値をすべて CSS 変数にし、3つのテーマ（抹茶・石・墨）を切り替えられるようにする

- 重大度：中
- 分類：保守性
- 状態：完了（PR で実装。部品の CSS の色コード・px の文字サイズは、テストで残さない。実機の見え方は持ち主が確認する）

**問題の内容と該当箇所**

- `styles.css` の先頭（1〜47 行）に変数はあるが、名前が素材の比喩（`--paper`・`--ink`・`--rule`・`--red` など）で、役割が読み取りにくい。テーマは `light`／`dark` の2つだけ（`html[data-theme="dark"]`）
- 部品の CSS に、色コードが直接書かれている（ゲーム風の帯 `.quest*`、ダイアログの後ろの幕、色見本の縁など。約30か所）。px の文字サイズも約20か所ある（`.brand` 21px、`.count b` 34px など）
- 余白・角の丸み・影は変数になっていない
- テーマの設定（自動／ライト／ダーク）は `db.settings.theme` にあり、`app.js` の `applyTheme`（4473 行付近）が `app.js` の読み込み後に付ける。そのため、起動の瞬間に別のテーマで一瞬描かれることがある
- ブラウザの上端の色（`<meta name="theme-color">`）は、`applyTheme` の中に色コードを直接書いている

**なぜ問題なのか**

色や大きさを変えるたびに、部品の CSS を探して書き換えることになる。テーマを足すと、書き換えの漏れがそのテーマだけに残る。

**改善案（持ち主が 2026-11-09 に了承した内容）**

1. 見た目の値（色・文字・余白・角・影・動き・重なり）を、すべて `styles.css` の先頭の CSS 変数にまとめる。部品の CSS には色コードと px の文字サイズを書かない
2. テーマは `html[data-theme="matcha"|"stone"|"dark"]` で、変数の値だけを上書きする
3. テーマは3つ：抹茶（matcha、落ち着いた緑）・石（stone、灰色）・墨（dark、ダーク）。今の「自動／ライト／ダーク」を置き換える
4. 選んだテーマは、この端末のブラウザ（localStorage）に保存し、次回も同じテーマで開く。同期はしない。localStorage が使えない環境（プライベートモードなど）でも例外を出さず、既定のテーマで開く
5. まだ選んでいない端末は、端末の設定がダークなら墨、それ以外は抹茶で開く。旧設定は一度だけ引き継ぐ：ライト→抹茶、ダーク→墨。自動は「まだ選んでいない」と同じ扱い
6. 画面を描く前にテーマを決める（ちらつきを防ぐ）。CSP（`script-src 'self'`）で `<head>` に直接スクリプトを書けないので、小さな別ファイル `theme-boot.js` にする
7. 見た目の方向：角は 2px から 6px（ボタン・カード）・10px（ダイアログ・パネル）に、影は抹茶・石だけごく薄く付ける（墨は影なし）。紙の手帳の世界観（罫線・判子・演出の「手帳風」）は残す
8. 切り替えは、設定の「表示テーマ」と、見出しの右上の ◐ ボタン（押すたびに 抹茶→石→墨）の2か所

**変数の命名ルール**

- 名前は `--種類-役割-段階`（Astryx と同じ）。部品は意味の変数だけを参照する
- テーマに関わらない値（文字・余白・角・動き・重なり・寸法・ゲーム風の帯の色）は `:root` に1回だけ書く
- テーマで変わる値（色・影）は、3つのテーマのブロックに、同じ名前をすべてそろえて書く（抜けがあると、そのテーマだけ前のテーマの値が残る）

**実装担当への指示文**

> 目的：見た目の値をすべて CSS 変数にまとめ、3つのテーマ（抹茶・石・墨）を、変数の値の上書きだけで切り替えられるようにする。データ・同期・Worker は変えない。
> 対象ファイル：`styles.css`（全体）、新規 `theme-boot.js`、`index.html`（`<head>` と見出し）、`app.js`（`db` の初期値 105 行付近、設定の「表示テーマ」2555 行付近、ファイルからの読み込み 2632 行付近、`applyTheme`・`matchMedia` の監視 4473〜4479 行付近、起動 4630 行付近、歯車ボタン 4628 行付近）、`scripts/build.mjs`、`service-worker.js`、テスト `test/unit/build.test.js`・新規 `test/unit/theme.test.js`、`docs/DESIGN-IMPROVEMENTS.md`（「今のデザインの方針」）。
> やること：
> 1. `styles.css` の先頭の変数を、上の「変数の一覧」と「3つのテーマの配色」のとおりに書き直す。`:root` にテーマに関わらない値と抹茶の値（`:root, html[data-theme="matcha"]`）を置き、`html[data-theme="stone"]`・`html[data-theme="dark"]` で色と影を上書きする。各テーマのブロックに `color-scheme`（light／dark）も書く
> 2. 部品の CSS の旧い名前を、新しい名前に置き換える：`--paper`→`--color-background-body`、`--card`→`--color-background-surface`、`--ink`→`--color-text-primary`、`--ink-2`→`--color-text-secondary`、`--ink-3`→`--color-text-tertiary`、`--rule`→`--color-border`、`--rule-2`→`--color-border-subtle`、`--red`→`--color-danger`、`--amber`→`--color-warning`、`--blue`→`--color-info`、`--routine`→`--color-routine`、`--mark`→`--color-mark`、`--mark-ink`→`--color-on-mark`、`--grass-N`→`--color-heat-N`、`--grass-edge`→`--color-heat-edge`、`--fs-*`→`--font-size-*`、`--sans`→`--font-family-body`、`--num`→`--font-family-num`、`--radius`→`--radius-element`。置き換えは `var(--旧名)` の形だけを対象にし、`--ink` と `--ink-2` のように前方が同じ名前を取り違えない（長い名前から先に置き換える）
> 3. 部品の CSS に直接書かれた色を変数にする：ゲーム風の帯（`.quest*`）の色は `--color-fx-*`（値は今のまま）、ダイアログの後ろの幕は `--color-overlay`、確認の幕は `--color-overlay-light`、色見本の縁は `--color-swatch-edge`、見出しのタブの赤い数字の文字（`#fff`）は `--color-on-danger`
> 4. px の文字サイズは、上の対応表のとおり `--font-size-*` にする（`clamp()` の中も変数にする）。`font-weight:700`・`500` は `--font-weight-bold`・`medium` に、本文の行の高さは `--line-height-body` にする。`padding`・`margin`・`gap` の 4・8・12・16・20・24・32px は `--spacing-*` にする（負の値と `calc()` の中の計算は、壊さないように残す）
> 5. 角と影：`border-radius` の 1〜3px は `--radius-inner`、今 `var(--radius)` のものは `--radius-element`（6px）、ダイアログは `--radius-container`。カード（`.card`）と設定の枠（`.sec`）に `--shadow-low`、ダイアログと登録ボタン（`.fab`）に `--shadow-med` を付ける。フォーカスの枠（`:focus-visible`）は `--color-focus` にする
> 6. 新規 `theme-boot.js`：`THEMES`（`matcha`・`stone`・`dark`）・`THEME_NAMES`（抹茶・石・墨）・`resolveTheme(saved, prefersDark)`・`readSavedTheme()`・`saveTheme(name)`・`bootTheme()` を置き、読み込んだらすぐ `bootTheme()` で `<html data-theme>` を付ける。保存の鍵は `deadline-tracker-theme`。localStorage と `matchMedia` に触る所はすべて try/catch で包み、使えなければ既定（端末がダークなら墨、それ以外は抹茶）にする。3つ以外の値は保存しない
> 7. `index.html`：`<link rel="stylesheet" href="styles.css?v=dev">` の直前に `<script src="theme-boot.js"></script>` を置く。`<meta name="theme-color">` の初期値を抹茶の背景（`#F0F0E0`）にする。見出しの歯車の左に、テーマの ◐ ボタン（`id="themeBtn"`、クラス `gear gear--theme`、`aria-label` は「テーマ：抹茶（押すと石に切り替え）」の形）を足し、`styles.css` に `.gear--theme{right:36px}` を足す
> 8. `app.js`：`db.settings` の初期値から `theme:"auto"` を外す。設定の「表示テーマ」を抹茶・石・墨の3つのチップにする（説明：「見出しの右上の ◐ でも切り替えられます。まだ選んでいないときは、端末がダークモードなら墨、それ以外は抹茶です。この端末だけの設定です」）。`applyTheme(t)` は `<html data-theme>`・`theme-color`（`getComputedStyle` で `--color-background-body` を読む）・◐ ボタンの `aria-label` を更新する。`setTheme(t)` は `saveTheme(t)` してから `applyTheme(t)` する（保存できなくても、その回は切り替わる）。◐ ボタンは押すたびに次のテーマにし、トーストで「テーマ：石」のように知らせる。起動時は `load()` の後に、旧設定の引き継ぎ（`db.settings.theme` が `light` なら抹茶、`dark` なら墨を保存。まだ保存が無いときだけ。終わったら `db.settings.theme` を消す）をしてから `applyTheme()` する。端末のダーク設定が変わったときは、まだテーマを選んでいない端末だけ描き直す。ファイルからの読み込みの後の `applyTheme()` は要らない（テーマはデータに入らない）
> 9. `scripts/build.mjs` の配信するファイルと版の計算（`files`・`STAMP_SOURCES`・`hash10` に渡す内容）に `theme-boot.js` を足す。`service-worker.js` の `CORE_FILES` にも足す。`test/unit/build.test.js` の版のハッシュの期待値も、`theme-boot.js` を含めた形に直す
> 10. 新規 `test/unit/theme.test.js` に、次を確かめるテストを書く。`theme-boot.js` は偽の `window`・`document` を渡した `vm` の中で動かす
>     - まだ選んでいない端末：端末がダークなら墨、それ以外は抹茶
>     - 選んだテーマを保存し、次回は端末の設定より優先する。旧設定の値（`light`・`auto`）や知らない値が保存されていても既定で開く。3つ以外は保存しない
>     - localStorage に触ると例外になる環境でも、例外を出さずに既定で開く
>     - `styles.css` の部品の CSS（`*{box-sizing` より後）に、色コード（`#…`・`rgb()`・`rgba()`）と px の文字サイズが無い（コメントの中は除く）
>     - 3つのテーマのブロックが、同じ名前の色・影の変数をすべて定義している
>     - 部品が参照している変数（`var(--…)`）は、すべて定義されている。部品の中で定義する局所の変数と、`app.js` が `data-st` で付ける変数（`--to`・`--hh`・`--d` など）は除く
>     - どのテーマも、上の配色の表の組み合わせが WCAG AA（本文 4.5 以上・枠とフォーカス 3 以上）を満たす（比を計算する）
> 11. `docs/DESIGN-IMPROVEMENTS.md` の「今のデザインの方針（守るもの）」の1行目（角 2px・影なし）を、D21 の内容（角 6px・抹茶と石だけ薄い影）に書き直す
> 12. `index.html` の `app-version`・`package.json` の minor を上げ、`docs/VERSIONS.md` に1行足す。README の「表示テーマ」の説明を直す
> 制約：ES5 風の書き方（`app.js`・`theme-boot.js`）。外部の CSS フレームワーク・React・Astryx を入れない。依存を足さない。HTML に `<script>` や `style` 属性を直接書かない（CSP）。データの保存・同期・Worker・通知は変えない。テーマの設定は同期しない（端末ごと）。
> 完了の条件：`npm test` と `npm run build` が成功する。PC（幅1280px）とスマホ（幅375px）で、3つのテーマすべての画面を確かめ、スクリーンショットを PR に載せる。プライベートモード（localStorage が使えない）で開いても、エラーにならず表示される。キーボードだけで ◐ ボタンと設定のチップを操作できる。コミットメッセージは `feat: 要約`。
